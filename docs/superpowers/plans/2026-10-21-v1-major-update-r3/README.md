## 2. 研究后的核心判断

忆涟千言已经有工作台、消息分支、资源存储、智能体绑定、工具安全网关、任务图、ProofLoop、模型池与语音宿主。主要问题不是再建一套通用 Agent 平台，而是把这些能力在普通聊天入口接通，补齐必要的新能力，并把状态和结果安排到合适的页面。

Cyrene 值得参考的是场景上下文、可恢复运行、按需打开的文件/差异面板、工具和知识在对话中的真实消费。其 Electron 宿主、Node 插件执行、特定渠道授权策略和角色化功能不能直接成为我们的架构。

本版选择：**保留现有入口与领域，补齐共享运行上下文，让能力在当前任务中按需出现。**

比较过的其他方案：直接移植 Cyrene 会改变技术栈与插件边界；继续堆叠独立创作中心、代码中心、任务中心会重复 Workspace/Resource/Task 的职责。二者都不采用。

## 3. 必须纠正的旧版设计

| R1/R2 表述或设计 | R3 修正 |
|---|---|
| 把我们的消息画布画成几个任务标题相连 | 画布保留用户提问、助手回答与回答分支；工具过程不变成节点 |
| 设置画布只画四个大分类，中心为“小涟” | 全局中心为“忆涟设置”，保留六组：模型与服务、语音、智能体与上下文、安全、界面、扩展；编辑特定 agent 时才显示它的绑定 |
| 将附件当作从零增加的功能 | 上传、预览、会话绑定已存在；重点是普通聊天读取绑定资源和模型可见内容 |
| 普通对话直接复用 Artifact 的所有方法 | Artifact 当前要求 task/execution；新增 Resource 关联成果投影，只有真实任务产物才引用 Artifact |
| 新建另一套前端 run store | 继续由现有 conversationRuntime 管理会话；增加轮次身份与恢复信息，不复制状态机 |
| 把待回答卡全部视为新 subsystem | 已有 TaskDecision，但目前 task_id/execution_id 必需，解决接口未形成通用聊天续接；共享输入控件、分别接入已有任务与聊天 owner |
| “当前任务”入口统一跳转目标详情 | 该入口当前明确指向消息画布且有测试；保留它，另在真实任务结果处提供准确跳转 |
| Cyrene 的 Chat 一律无工具 | 当前 run-capabilities 已允许 chatBuiltin 和用户 opt-in 工具；不能只按 README 下结论 |
| 把 Cyrene 浏览器当作可直接嵌入的网页组件 | 它使用 Electron WebContentsView；我们继续用现有 Playwright MCP context 与证据视图 |
| 定时任务照搬无人值守策略 | 不采用参考源码的 allow_all；仍经过现有网关，等待批准可由桌面继续 |
| 新增接口表很多，但缺少写入责任 | 新规格明确每项数据的唯一 owner、现有/新增接口和失败后的真实状态 |
| 默认把模型、资料、进度、验收全放首页 | 默认只有会话和当前结果；高级面板按动作出现，必要审批与错误仍清楚显示 |

## 4. 一次完整更新的成果

本次更新交付 12 个功能包，它们是职责边界，不是开发阶段：

| 包 | 用户最终能做什么 |
|---|---|
| P01 普通聊天的真实输入 | 附件、工作空间、知识范围、角色、模型选择真正进入同一轮运行 |
| P02 连续运行与上下文 | 长对话可压缩、过程可恢复、必要问题可回答、停止与审批不串轮 |
| P03 资料与记忆 | 回答可定位来源；记忆有范围、来源、纠正和停用 |
| P04 成果交付 | 普通聊天、任务、图片、办公文档都能找到实际文件和来源，版本不串验收 |
| P05 代码协作 | 在选定目录阅读、修改、看差异、验证，再显式提交/推送 |
| P06 学习与持续创作 | 在同一空间阅读资料、形成笔记、作答、修订内容与导出 |
| P07 技能、工作流与插件 | 安装/发现/绑定/使用/停用闭环，保留可用性与缺失依赖的真实状态 |
| P08 时间任务与通知 | 创建明确时间任务，追踪触发，处理等待与错过；不擅自后台执行高风险动作 |
| P09 外部渠道 | 分别配置渠道账号与会话范围，消息进入现有运行，发送结果可追踪 |
| P10 语音与个人化 | 文字、语音、角色和当前会话一致；打断、结束、提醒各有明确含义 |
| P11 页面与会话体验 | 现有所有页面可达；搜索、分支、成果、资料与设置不要求用户跳过多层页面 |
| P12 生命周期与交付 | 首次配置、真实首次成功、导出/恢复、安装/退出与升级行为明确 |

保留上一轮提出的 OCR、PPTX、图片编辑、渠道等范围，但把它们列为真实新增能力，明确依赖与验收，不能将“有入口”算实现。音乐、动态流、Live2D 和 v2 桌面空间仍是独立产品扩展，不把整套陪伴产品并入本次 v1 Core。

## 5. 预览为何换成可点击原型

前两版生成图存在标签、结构和实际页面不一致的问题。R3 用 HTML/CSS 表达已核对的页面结构，复用项目已有昔涟背景与图标素材，再由浏览器渲染截图。这样字段、分类、空态和展开交互都可以逐项检查。

原型不是生产实现：使用固定示例数据，不调用模型、不连接数据库、不发消息、不执行工具。页面内的动作只演示导航、展开、选择与反馈；业务验收仍按开发规格执行。

## 6. 使用本版实施的前提

真正开工时重新核对分支、当前工作区与源码 hash；用户要求在当前分支时遵从用户，不自动建分支。已有功能先复用，不新增自动 fallback、静默修复、供应商降级或默认子智能体。既有审批、取消和验证约束保留。

交付需要真实功能、原有回归、页面交互与安装证据一起通过，不以原型、静态检查或历史测试报告替代。没有开发周期，也不把未完成的必选包拆成后续版本。
