# R3 页面与交互规格

返回 [总文档](README.md)。本版不是通用聊天产品换色，而是对当前忆涟工作台结构的整理。

## 1. 视觉与结构依据

使用当前 Cyrene token：背景 #F8F6FD、次背景 #f4f0fc、文本 #292536、次文字 #696276、玫粉 #ea91b9、导航 #29263a。保留当前项目的昔涟背景与应用标识；通过内容区底色和低透明度控制可读性，不在新模块另建主题。

主要导航保持主页、画布、工作空间、能力、更多，设置与账号在底部。应用 Logo 和头像入口保持当前意义。宽屏保留熟悉的会话列表，新增手动收起/固定；窄屏使用原有抽屉。默认关闭右侧详情，不因切换工作/创造自动打开 Git。

Cyrene 的按需 Inspector 可以借鉴，但我们的页面保持自己的 NavRail 与路由。六组设置、六类能力、用户/助手消息节点均来自已核对的当前实现。

## 2. 首页的三种状态

| 状态 | 默认显示 | 不常驻的内容 |
|---|---|---|
| 空会话 | 小涟问候、输入框、少量真实快捷入口 | 任务图、指标、验收卡 |
| 普通对话 | 用户问题、助手回答、必要附件/结果行 | 工具参数、引用全文、Git |
| 执行中 | 一句当前动作、展开过程、停止 | 完整执行日志和底层 ID |

需要询问时只显示当前问题，不同时列出无关计划、指标和交付确认。需要批准时原有批准 UI 保留明确动作和范围，不能为了简洁把批准藏进更多菜单。

输入框保留三模式单个菜单、附件、语音、当前模型名及发送。thinking 和更多配置在模型弹层里。只有用户选中资料或场景时显示对应小标签。当前模型名关系到真实费用与能力，不应像 R2 那样全部藏掉。

## 3. 20 个页面与关键状态的落点

| 原型编号 | 页面/状态 | 实际或拟定入口 | 核心交互 |
|---|---|---|---|
| 01 | 已有对话 | /chat/:id | 收起历史、展开过程、打开资料/成果 |
| 02 | 新对话 | /chat | 选模式与当前输入，显示首次使用入口 |
| 03 | 消息画布 | /connectors | 用户/助手节点、回答分支、定位对话 |
| 04 | 工作空间列表 | /workspaces | 新建/打开，不混入所有 task 指标 |
| 05 | 工作空间详情 | /workspaces/:id | 文件、任务、成果；Git 需明确选空间 |
| 06 | 能力入口 | /capabilities | 六类入口→当前管理弹窗 |
| 07 | 工具管理 | 能力→工具弹窗 | 紧凑列表→单项参数→返回 |
| 08 | 智能体 | /agents | 角色、提示词、能力绑定分别编辑 |
| 09 | 记忆 | /memory | 分类、范围、来源、纠正与归档 |
| 10 | 知识库 | /knowledge | 集合/文档列表→全文/引用→用于对话 |
| 11 | 设置总览 | /settings | 六组围绕“忆涟设置”，不重复创建新分类体系 |
| 12 | 设置分组展开 | /settings，当前 group | 点击展开子节点，再打开当前编辑器 |
| 13 | 监控 | /system | 资源与实际用量；不把本地运行写成一定在本地推理 |
| 14 | 日志 | /logs | 筛选→一条记录→关联会话/运行 |
| 15 | 账号与隐私 | /account | 游客/登录、同步、导出/恢复与隐私 |
| 16 | 首次配置 | /setup | 当前步骤表单，连接测试与保存分开 |
| 17 | 时间任务 | /automations，拟新增 | 定义、下次触发、在途与历史 |
| 18 | 消息渠道 | /channels，拟新增 | 分别配置账户与回复范围；未连接就明确未连接 |
| 19 | 资料学习 | Workspace 学习页签，拟新增 | 当前资料、笔记/练习；答案提交前不返回 |
| 20 | 创造与成果预览 | Workspace 成果页签或当前输出面板 | 文件预览、来源、版本、导出 |

更多页作为现有目录容器：保留智能体/记忆/知识/监控/日志入口，补时间任务和渠道；插件功能仍由 `/more/plugins/:pluginId/:featureId` 承载。它们不另建新的主导航。语音沿用全局浮层，主窗口/圆形悬浮形态保留，不把通话变成新的页面系统。

## 4. 展开行为

- 历史和当前辅助面板由用户控制，默认不同时增加两条新的右侧栏。
- 消息中点击文件优先在当前辅助区域预览；打开知识引用定位到 document/hash/offset；不存在来源显示已删除。
- 工具列表、Skill 和 MCP 仍由各自管理器处理；关掉弹窗回到能力分类，不丢失原搜索条件。
- 设置“居中”仅改视口，“整理布局”才改坐标；展开分类保留其他配置，不因隐藏节点就停用功能。
- 消息分支只在合法回答边界提供入口，不将工具调用、推理文本或审批节点画入消息树。
- 代码和学习选择放在工作模式下的预设菜单，不和聊天/工作/创造并列成五个模式。

## 5. 原型可做什么

原型提供页面导航、历史收起、过程展开、辅助面板、设置分组、能力/工具详情、知识阅读、账号区域、练习提交和时间任务编辑等演示。

全部数据带原型语义：文件、状态与输入是示例，不读取用户文件，不发模型请求，不实际发消息、执行 Git、保存凭据或运行时间任务。功能按钮的演示反馈不会宣称已完成真实业务。

截图由这一份 HTML/CSS 原型渲染，修订时文字和结构可精确检查。它不是生产 React 代码，也不是当前 Tauri 运行截图。现有真实截图仍链接在研究证据中，用于区分基线与提案。

## 6. 交互验收

1. 20 个主要页面/状态均能通过目录或页面内入口到达。
2. 默认聊天无右侧空白槽，打开详情后只出现一个辅助面板；关闭后输入宽度恢复。
3. 画布中的节点角色和分支边可辨认，工具过程只在展开区。
4. 设置六个分组均可点击，子项与当前代码分组一致。
5. 800×600 与 1440×900 下无横向溢出，输入、返回、关闭操作可达。
6. Esc 关闭弹窗，焦点返回触发项；Enter 不误发中文输入法组合文字。
7. 原型交互检查与产品功能验收分别记录，不把原型按钮响应当作后端能力通过。
