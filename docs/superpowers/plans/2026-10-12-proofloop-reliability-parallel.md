## 4. 阶段与并行关系

```text
R0 基线、共享类型与文件所有权
 ├─ A 中断结果与重入检查 ───────────────┐
 ├─ B 草稿 CAS 与确认一致性 ────────────┤
 ├─ C1 成果基础检查 → C2 精确检索 ──────┤→ R2 集成与产品回归
 ├─ D 活动计时与预算接线 ───────────────┤        ↓
 ├─ E 云冲突三态接线 ──────────────────┘    R3 候选构建
 └─ V0 任务输入、服务、数据与判定器准备 ────────┤
                                               ↓
                                    R4 真实业务、桌面、对照实验
                                               ↓
                                          R5 独立终审
```

| 阶段 | 开始条件 | 并行任务 | 退出门槛 |
|---|---|---|---|
| R0 | 确认共同基线 | 集成人统一共享 DTO；各线阅读调用链 | 类型契约可消费，文件无多写者 |
| R1 | R0 接口冻结 | A、B、C、D、E 和 V0 同时推进 | 每包负例、正例、独立测试及必要构建通过 |
| R2 | 对应工作包可集成 | 分批合并；产品回归随已合入功能推进 | 六类问题全部有产品或接口证据，共用路径无绕行 |
| R3 | R2 通过 | Windows 候选构建；外部环境预检查 | 候选提交、制品摘要与运行版本可对应 |
| R4 | 候选可运行且服务可用 | ProofLoop 实验、桌面生命周期、两设备冲突可分人进行 | 原始数据齐备，失败与未测均保留 |
| R5 | 证据清单稳定 | 独立审查 | 按 G 文档给出实际结论 |

C1、C2 归同一写入责任人，避免同时改 `evidence.rs`。D 的独立计量实现不等待 A，但 D 的运行时接线在 A 合并后完成。B 与 D 都涉及 `db/proofloop.rs`，由集成人按 B→D 顺序应用小补丁；D 不整文件覆盖 B 的 CAS。

R01 是最先交付的 P0。它可以独立集成，不等待真实模型环境、预算配置 UI 或其他工作包全部完成。V0 可先准备实验输入，但真实业务运行要等 R01 与成果基础检查通过。
