## 结论格式

最终审查报告放在 `docs/v1.1/reliability/focused-review-2026-10-10.md`（实施完成后才创建）；包含：

```text
candidate: CLIENT commit / SERVER commit / installer SHA-256
reviewer: 人员/会话；是否参与实现
R01..R06: FIXED / STILL_OPEN，附代码位置和用例证据
D01..D05: PASS / FAIL / NOT_TESTED
E20..E22: PASS / FAIL / NOT_TESTED
scope: 是否违反严禁防御性开发约束
hosting: 之前推送已授权；未来政策决定单独记录
decision: READY_FOR_RELEASE / NEEDS_FIX / ACCEPTANCE_INCOMPLETE
```

判定规则：

- `NEEDS_FIX`：有已确认缺陷未修、回归、伪成功，或某个必需验收实际 FAIL。
- `ACCEPTANCE_INCOMPLETE`：代码修复通过，但两设备或 E20—E22 存在未执行/证据不能对应候选。
- `READY_FOR_RELEASE`：R01—R06 修复成立，两设备和 E20—E22 通过，范围及源码边界符合约定。

R07“永久注销加二次认证”不作为本轮阻断条件，不在临门验收时临时升级为需求。未来托管规则的人工决策独立展示，不虚报已批准，也不否认此前明确的推送授权。

审查结论不自动执行生产部署、推送或发布标签；按会话中实际已获授权的范围继续交付。
