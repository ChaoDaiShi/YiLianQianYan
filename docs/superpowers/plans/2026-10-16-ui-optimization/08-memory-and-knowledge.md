## F1 记忆列表与详情

- [ ] 保留分类选项和来源选项的真实常量，不自行新增document等后端没有使用的来源值。
- [ ] 页头下安排分类、来源和搜索，较窄时换行；筛选变化不把整页刷新成空白。
- [ ] 正文摘要是卡片主内容，使用16px正文和1.55行高；分类与来源用13px辅助文字。

- [ ] “无记录”与“无匹配结果”文案分开；后者有清除筛选。

验收F-01：短文、2000字长文、长URL和多行文本可读；F-02：分类/来源/搜索联动，清除后恢复当前数据。

## F2 增改删状态

- [ ] 读取当前handleAdd/handleEdit/handleDelete与Store返回结果，继续使用原操作函数。
- [ ] 新增与编辑分别维护各自提交中状态；保存按钮busy，不清空输入直到成功。
- [ ] 失败时Modal保持打开、正文保留、错误可见；成功才刷新真实记录并关闭。
- [ ] 删除使用原确认规则和API结果；失败不把卡片从列表移除；成功后选中下一条现有记录或关闭详情。
- [ ] 注意返回类型：addMemory返回记录或null，editMemory返回boolean，removeMemory返回void且在Store中记录error。删除后用 `useMemoryStore.getState()` 的error与记录是否仍存在判断显示结果，不能把await结束当成删除成功，也不能为方便UI改变Store签名。
- [ ] 操作图标hover/focus-within均可见；键盘焦点经过删除按钮不会触发整行选择两次。
- [ ] 详情布局调整不能隐去已有MemorySkillCandidate相关业务入口在其他页面的展示；F只修改本页，不动C的任务成果区。

状态流：

```text
编辑原记录 → 输入草稿 → 点击保存 → 保存中
  ├─ 原操作返回成功 → 读取/展示实际保存内容 → 关闭编辑
  └─ 原操作失败     → 保留草稿与编辑框 → 错误说明 → 可再次保存
```

验收F-03：新增/编辑失败仍有原内容；F-04：成功后重新进入详情得到持久内容；F-05：删除失败记录仍在。
