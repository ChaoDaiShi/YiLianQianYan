# 11 可复制的智能体任务提示词

## 1. 使用方式

用户先决定交给哪个会话执行哪个工作包，再把“通用启动约束”和对应包提示词一起发送。文档本身不授权创建子智能体，也不意味着现在开始开发。

执行者不需要理解全部系统：先核对文件，再完成一个任务卡，跑该任务验证，记录证据，再做下一卡。公共文件需要变化时找所有者接线，不能自行扩张范围。

## 12. 单任务完成报告模板

此表是字段定义，使用时填写当次真实内容，不照抄成完成证明。

| 字段 | 必填内容 |
|---|---|
| 工作包/任务 | 例如B/B3，不能只写“前端优化” |
| 候选 | 当前SHA、分支、未提交文件范围 |
| 修改文件 | 实际新增/修改的完整清单 |
| 行为变化 | 触发操作、旧表现、新表现 |
| 数据来源 | 使用哪个API/Store字段，哪些是测试夹具 |
| 保留能力 | 本包涉及的附件/语音/审批/资源等回归结果 |
| 验证 | 命令、退出码、用例ID、截图路径 |
| 结果 | PASS/FAIL/NOT TESTED，分别列项 |
| 待接线 | 精确文件、参数、负责人、依赖门槛 |
| 范围外 | 例如未恢复四主题、未新增置信度，解释对应无数据原因 |

## 13. 卡住时怎样继续

1. 公共参数未实现：只暂停调用该参数的接线，继续本包独立布局和阅读状态。
2. API没有字段：按00决定隐藏该指标或显示明确未接入，不造字段、不自动开发后端。
3. 源码与文档不同：引用实际路径/函数，更新最小受影响任务并交给I统一合同；不要凭旧行号替换整段代码。
4. 测试失败：保留证据，定位当前改动，窄修后重跑原用例；不删旧能力或降低断言来通过。
5. 需要写他人文件：提交02共享变更申请。未收到接线结果前，不越权修改。
6. 无浏览器/桌面条件：先交付可核验的代码与构建结果，相关运行项写NOT TESTED；不可宣布完整UI验收通过。
