# 09 工作包 G：设置、系统监控与日志

**目标：** 用户知道修改是否保存、服务是否真实可用，能快速读取系统状态和定位日志。

**输入：** 六组设置、provider连接测试、SystemData/RuntimeHealth、LogEntry与现有轮询。**输出：** GG。

**可改：** 02中G的精确文件，拟新增 `frontend/src/styles/ui-optimization/settings-system.css`、`frontend/e2e/ui-optimization/g-system.mjs`。API、授权模型、凭据存储和后台采集只读。

## G1 设置页布局与外观预览

- [ ] 保留SETTINGS_GROUPS六组：模型、语音、智能体、安全、扩展、外观；继续支持旧 `?section=permissions/sandbox/skills/compaction` 映射。
- [ ] 导航目标200px；内容最大960px，不将复杂模型管理硬缩到760px。窄窗口改为顶部分类，正文单列。
- [ ] 每组使用SettingsSectionFrame和原section组件，只调整间距、卡片层级和字段对齐，不重新拼出一个大SettingsPage。
- [ ] 外观提供浅色/深色/跟随系统三个微缩预览卡；预览中的按钮/侧栏仅作示意，不承担实际导航。
- [ ] 点击预览调用theme.setMode；跟随系统显示当前resolvedScheme；不恢复PRESETS四主题选项。
- [ ] 背景上传、清除、重置沿用已有处理。预览使用同一已加载背景，不重新上传一次。
- [ ] 不提供当前applyTheme忽略的透明度/模糊滑块，避免滑块变化但实际页面不变。
- [ ] 表单标签与控件对齐，长说明放下一行；配置面板不因说明较长压缩密钥输入框。

验收G-01：六组和旧深链都可进入；G-02：浅深/系统与背景预览反映真实界面，重载模式保持。

## G2 保存、连接测试与权限展示

- [ ] 沿用comparableConfig和savedSnapshot判断普通配置dirty，不建立第二套配置比较算法。该函数有意排除密钥；用户只输入替换密钥时，用现有字段输入事件记录局部 `hasPendingSecretInput` 意图，保存栏显示条件为 `dirty || hasPendingSecretInput`，不能让密钥输入后保存按钮仍禁用。
- [ ] 固定栏包含“有未保存更改”“放弃修改”“保存设置”；和原页头保存动作复用同一handleSave，不允许同时发两次保存请求。
- [ ] 放弃修改恢复最近成功加载/保存的非敏感配置快照，并清除当前输入的替换密钥；不得从快照恢复或回显已保存密钥。
- [ ] hasPendingSecretInput只表示用户在本次表单写入了非空秘密输入，不从服务器返回的“已配置”标记推导；当前输入清空、成功保存或放弃后重算/清除。多个密钥输入任一仍非空就保持true；明确清除密钥的既有即时操作不进入此标记。
- [ ] 主题即时保存和后端配置保存是两种既有语义。外观页模式切换不能虚假点亮“后端配置未保存”，也不能被放弃后端修改悄悄重置。
- [ ] saving期间保持栏与按钮尺寸，保存失败保留草稿和错误；真正保存成功才更新savedSnapshot。
- [ ] provider测试复用verifyProviderConnection与当前providerTestResults；不同provider独立显示结果。
- [ ] 已保存但未测试写“已保存·未测试”；修改配置后旧测试结果不作为新配置成功。使用现有connectionPresentation语义。
- [ ] 仅替换密钥也会使旧测试结果过期；把 `dirty || hasPendingSecretInput` 传给展示判定。该处理只修正表单反馈，不改变密钥API和授权流程。
- [ ] 不显示180ms等虚构延迟；如未来显示本次请求耗时，要明确是客户端测试耗时，不是服务端延迟，本轮默认不加。
- [ ] 密钥掩码开关只切换本次输入文本的type；已保存只显示“已配置”，保留替换/显式清除语义。
- [ ] GrantEditor保留现有资源、权限和scope选项；按说明/控件两列排，不将它强行映射到原稿的四档授权。
- [ ] 未保存栏避开全局语音控件；窄窗口使用流内底栏或增加真实底部占位，不只提高z-index覆盖它。

| 状态 | 保存栏/测试展示 |
|---|---|
| 刚加载 | 无未保存栏；保持已有provider配置状态 |
| 普通配置改动 | 出现栏；保存可用 |
| 只输入替换密钥 | 显示待保存密钥输入；保存可用，旧测试结果失效 |
| 改动后测试 | 按现有测试语义消费当前配置；不把“已保存”文案附到未保存配置 |
| 保存中 | 处理中；输入保留 |
| 保存失败 | 错误可见；栏仍在 |
| 保存成功 | 真实快照更新；栏收起；成功提示短暂可见 |
| 放弃修改 | 恢复非敏感字段；清掉本次秘密输入；不改变已保存秘密 |

验收G-03：dirty/放弃/成功/失败；G-04：密钥保留/替换/清除不变；G-05：连接失败不显示绿灯；G-06：语音控件与保存按钮不重叠。

## G3 系统指标与健康区

- [ ] 使用getSystemInfo现有SystemData：CPU、内存、磁盘、GPU/主机信息；不引入网络采集。
- [ ] CPU/内存用数值+可选48px小环；磁盘按实际磁盘记录显示容量/用量，不能把各分区百分比直接平均。
- [ ] GPU仅有名称/显存/驱动时展示文本；不显示GPU使用率圆环。
- [ ] 显示百分比单位和更新时间。未加载使用骨架；失败显示错误，已有上次数据可标“上次刷新”保留。
- [ ] 正常/关注/高负载采用0≤p<70、70≤p≤88、88<p≤100三段；这是本轮显示分级，不声称系统报警标准。
- [ ] 超阈值仅使用状态色/文字，默认不持续脉冲，不触发新通知服务。
- [ ] 健康区仅展示RuntimeHealth明确的服务、版本、database和policy_version；没有SSE/MCP状态就不画绿色健康条。
- [ ] 现有MonitoringToolbox保持入口和动作，不重做系统采集与刷新周期。
- [ ] 如提供日志快捷入口，必须实际进入 `/logs`；没有对应source过滤协议时不要宣称已筛到该模块。

小环实现使用原生SVG：路径长度100，stroke-dasharray为 `p` 与 `100-p`，同屏始终有百分比文字；SVG标aria-hidden即可，避免屏幕阅读器读两次。p取现有percent解析结果，原始数值无效时不把它当真实0%展示。

验收G-07：真实字段对应、磁盘不错误平均；G-08：加载/上次数据/失败清晰，未提供数据无假值。

## G4 日志控制台与键盘检视

- [ ] 保留当前2秒轮询；状态文字为“自动刷新中”或“已暂停”，不用“SSE已连接”或未知积压量。
- [ ] 工具栏包含级别、来源、搜索、暂停/继续和已有清空；标签计数仅表示当前已加载范围，不能当后端全量计数。
- [ ] 日志行用时间/级别/来源/正文四列，目标110/68/140/剩余px；行最小32px，正文省略后可打开完整详情。
- [ ] WARN/ERROR用浅语义背景与左边框，仍保留级别文本。深色模式不能用浅色固定底把文字冲淡。
- [ ] 搜索用文本分段高亮，不通过dangerouslySetInnerHTML插入日志内容；保持日志文本原样可复制。
- [ ] 详情显示LogEntry的timestamp、level、source、message；原始JSON就是该对象，不虚构payload或trace字段。
- [ ] 上下键仅在日志列表焦点内切换visibleEntries；输入框内上下键保持原编辑用途。
- [ ] 暂停停止自动拉取，继续后按现有获取逻辑刷新；不推算暂停期间漏了多少条。
- [ ] “清空日志”当前调用getLogs({drain:true})，涉及后端日志缓冲区；保留真实作用范围，不能改文案成“仅清空当前视图”。使用独立测试后端验证。
- [ ] 用户上滚时不拉回底部，提供“回到最新”；旧selectedEntry仍可读，后续刷新不能在同位置换成另一条日志。

当前LogEntry没有id。保持选中对象或稳定组合定位，不使用数组下标作为跨刷新唯一身份；本轮不增加数据库/后端日志ID。

验收G-09：级别/来源/搜索组合正确；G-10：暂停无自动请求，继续恢复；G-11：详情复制完整与上下切换；G-12：清空真实范围和滚动行为。
