# R2：完整产品覆盖与简洁交互

返回 [主开发文档](../2026-10-21-v1-major-update.md)。本修订回应用户要求：功能方案与各页面预览同时补齐。没有开发周期；以下均为拟实施规格。

## 1. 修订的重点

第一版着重运行、状态、接口与验收，对普通会话操作、创作工具、个人化体验和应用生命周期写得不足。第一张预览又把这些状态集中铺在首页，导致产品能力和页面复杂度同时增加。

R2 用三个显示层次组织完整功能：

| 显示层 | 用户看到什么 | 何时出现 |
|---|---|---|
| 日常使用 | 对话、输入、简短过程、当前成果 | 默认 |
| 当前操作 | 选资料、改模式、看来源、回答问题、审批、文件预览 | 用户打开，或当前动作确实需要 |
| 专项管理 | 角色、记忆、知识、能力、渠道、设置、日志、监控 | 进入对应页面 |

“简洁”不减少能力，也不隐藏错误和审批；只是让同一时刻的界面围绕当前动作展开。

## 3. M12：会话基础操作

**复用文件：** `frontend/src/components/chat/MessageBubble.tsx`、`ChatInput.tsx`、`ConversationSidebar.tsx`、`frontend/src/api/conversations.ts`、`backend/src/api/conversations.rs`、`backend/src/db/conversations.rs`、`backend/src/db/connector_messages.rs`。

**拟新增落点：** `backend/src/api/conversation_actions.rs`、`frontend/src/features/conversation/ConversationActions.tsx`。

1. 历史抽屉支持标题/内容搜索、重命名、置顶、归档和删除；归档不删除消息，删除明确影响关联的消息分支。
2. 编辑旧用户消息创建新分支；重新生成创建兄弟回答分支。旧回复、旧成果与其验证结果仍属于原分支。
3. 运行中只允许停止，不同时对该轮重新生成；新分支不得继承执行批准。
4. 输入草稿按会话持久化；新会话草稿与已有会话分开，清除草稿不删除历史。
5. 附件上传显示实际上传/解析状态，失败可移除；只有成功取得 resource_id 才能发送。
6. 导出 Markdown/JSON 保留用户可见消息、来源和文件引用；不导出密钥，不把隐藏运行提示词并入聊天正文。
7. 回复操作默认低对比度显示复制/朗读，编辑/重新生成/分支放到消息菜单；不在每条消息旁常驻一排按钮。

完成条件：搜索命中正文；编辑/重新生成不会改写原历史；切换页面草稿保留；附件失败不出现虚假的可用资源；导出后可核对来源。

## 4. M13：多模态与办公文档

已核对：`backend/src/tools/basic_services.rs` 有图片等基础服务入口；`backend/src/modules/resource/document.rs` 明确说明图像与扫描 PDF OCR 暂不支持；`backend/src/modules/task/deliverable_renderers/mod.rs` 已有 Markdown/JSON/DOCX/XLSX/PNG/PDF 格式。以下补齐不能重写这些已有能力。

**拟新增落点：** `backend/src/modules/resource/ocr.rs`、`backend/src/modules/resource/parsers/pptx.rs`、`backend/src/modules/task/deliverable_renderers/pptx.rs`、`frontend/src/features/creation/CreationPanel.tsx`。

| 功能 | 输入 | 结果 | 必须核对 |
|---|---|---|---|
| 图片理解 | 用户选择的图片 Resource 与问题 | 描述/提取结果及原图引用 | 当前 vision 服务实际接受该图片 |
| 图像生成 | 描述、尺寸、用户显式选择的服务 | 图片 Resource | 文件真实可解码，尺寸与格式真实 |
| 图像编辑 | 原图 Resource、修改要求 | 新图片版本与 parent_resource_id | 不覆盖原图；服务明确支持编辑，不能用重新生成冒充 |
| OCR | 图片或扫描 PDF、用户选择 OCR | 页级文本、页号、原文图像引用 | 无文字页不伪造内容，提取失败有页级结果 |
| PPTX 读取 | PPTX 文件 | 幻灯片顺序、文本、备注与来源页 | 顺序正确，空白页保留页号 |
| PPTX 生成 | 标题、章节、图片/图表资源与版式 | 可打开的 PPTX | 不将 HTML/PDF 改扩展名；有真实幻灯片预览 |
| DOCX/XLSX/PDF | 已有结构化内容与用户格式选择 | 实际文档及预览 | 打开可读，中文字体、表格、分页正确 |

图片编辑、OCR 和 PPTX 需要各自能力状态，不得用“基础服务已配置”代替。缺少服务直接说明该操作尚不可用，不自动换供应商或静默转成另一种产物。

输出预览在专用面板中展示；对话里只放缩略图或文件行。生成进度一行呈现，查看细节时展开。图片/文档示例不证明真实服务已验收。

## 5. M14：角色、用户偏好与陪伴体验

已存在 `backend/src/api/agent_persona.rs` 的 AgentProfile 与 Persona，包含名称、角色描述、语气、语言和头像引用。保留该结构，补充使用和控制流程。

1. 智能体页编辑角色并提供“试聊”；试聊使用独立临时会话，用户可以保存为普通会话，也可以删除。
2. 用户称呼、输出语言、回答长度、常用工作空间由用户显式设置；与系统执行规则、权限和工具说明分开。
3. 区分长期偏好与当前项目状态；当前项目变化不能自动覆盖长期个人信息。
4. 每个角色可以选择已有 TTS 声音与语言；语音试播必须是实际 provider 返回的音频。
5. 主动提醒可设置是否启用、静默时段和提醒类型；默认不发起未经配置的问候或消息。
6. 角色停用后用户提示词是否继续生效按当前 AgentProfile 语义执行，UI 清楚说明；不能把“关闭角色”解释成清空用户数据。
7. 不显示亲密度、情绪或人格准确率等没有可靠数据依据的数值；不把角色表现依赖到 Live2D。

完成条件：同角色在文字、语音、已启用渠道的基本偏好一致；关闭提醒后不再触发；试聊和正式对话历史不混写。

## 6. M15：成果与持续创作

**复用：** 现有 Resource/Artifact、工作空间和 M07 笔记。**拟新增：** `backend/src/db/artifact_versions.rs`、`frontend/src/features/creation/ArtifactEditor.tsx`。

1. 工作空间“成果”页签按文稿、图片、办公文档筛选，显示名称、最近修改与来源会话。
2. 从成果打开原会话、查看来源、复制为新创作，必须保持原始 artifact/resource 身份关系。
3. 用户编辑文本后生成新版本；重新生成图片或文档同样产生新版本。每版记录作者类别 user/agent、parent ID 和创建时间。
4. 文本版本可比较差异，图片版本可并排查看。恢复旧版创建新 current 指针，不删除中间历史。
5. 用户手工修改产物后，旧内容验收不能继续标为当前版通过；应按当前版重新检查。
6. 导出是独立动作：下载到浏览器、另存到工作空间、在系统应用打开分别显示实际结果。
7. 删除一个成果版本不级联删除原始知识资料；若有当前版引用，明确提示后再处理指针。

完成条件：生成→用户修改→再次生成→版本比较→导出可走通，历史来源与验收不串版。

## 7. M16：外部消息渠道

本模块修订主文档第一版把渠道排除的范围决定。目标是逐渠道提供真实配置与收发闭环；不能将资源 connector 更名为渠道后宣称完成。

**拟新增：** `backend/src/modules/channel/{mod,model,service}.rs`、`backend/src/modules/channel/adapters/{feishu,weixin_ilink,onebot}.rs`、`backend/src/api/channels.rs`、`backend/src/db/channels.rs`、`frontend/src/features/channels/ChannelsPanel.tsx`。

- 飞书、微信 iLink、QQ/OneBot 分别提供 setup/validate/connect/disconnect 状态；外部协议由各自 adapter 负责。
- 真实账号、外部消息协议字段和 SDK 版本在实现时根据对应官方/协议文档核验；此处只冻结内部契约，不编造供应商地址或认证方式。
- 按 channel_account + external_conversation 关联本地 conversation；桌面可查看来源，用户不显式合并就不能混合多个外部联系人的上下文。
- 接收事件转成普通用户轮次；回复使用同一运行时与角色，但渠道默认只启用用户选择的能力，不能远程继承桌面全部文件/控制权限。
- 外发行为必须符合用户显式配置的回复范围和既有批准规则。未授权主动消息不发送；需要批准时停在待批准状态。
- 文本和附件分别记录真实发送结果；断开或结果未知时显示失败/未知，不改投另一渠道、不自动重复发送。
- 停用账号后停止接收和新回复，保留已存对话；删除账号不自动删除所有聊天，需要独立数据操作。

预览入口放在“更多”中的渠道页；配置服务凭据仍通过设置编辑器。桌面首页不增加三个渠道状态栏。

完成条件：每种渠道都有受控适配测试及真实账号的接收、回复、附件/不支持说明、停用验证。没有真实账号时标 BLOCKED，不将另外一个渠道的成功算作全部成功。

## 8. M17：首次成功、后台、退出与升级

1. 配置向导保留身份/模型/搜索/语音结构；登录可选，只让当前步骤展示当前表单。
2. 模型保存、测试连接、首次真实回复分别显示结果；测试失败保留用户输入，不自动换 provider。
3. 首次成功后提供一次“选择工作空间并完成小任务”的可跳过引导，不每次启动弹出。
4. 关闭窗口、保持后台运行、退出应用分别说明；定时任务依赖后台进程。退出前展示在途任务是否需要停止，由用户选择。
5. 更新入口显示实际版本与发布来源；用户触发下载/安装，不引入未授权自动更新。
6. 升级沿用既有迁移机制；本地数据导出与恢复使用显式操作，恢复前展示范围和将被替换的数据。
7. 账号/隐私页管理记忆、知识、成果、渠道账号、调度记录的导出与删除；凭据不进入普通导出。

完成条件：新安装用户可完成首次真实对话；退出不留无主任务；升级后旧数据可用；用户导出/恢复有可核对结果。

## 10. 预览图的实现约束

预览图用于评审默认页面的布局与视觉。用户选择选项后会出现相应编辑器，不要求把全部状态绘制在同一张图上。所有图中任务、文件、时间和状态均为示意数据，不能作为当前程序运行证据。

图中的自然语言、图标和尺寸需要在实现时用真实组件落实。若生成图片包含错字、示意文件内容或超出当前实现的陈述，以正式规格为准，不照抄图中技术命令。采用统一 token 和既有页面组件，不增加第二套设计系统。
