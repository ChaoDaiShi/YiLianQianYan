# v1 重大更新验收规格

## 1. 验收状态与证据

本文是待执行验收，不是测试报告。本次文档编写没有运行产品测试，以下所有产品用例初始状态均为 `NOT TESTED`。

允许状态：`PASS`、`FAIL`、`BLOCKED`、`NOT TESTED`、`HUMAN_PENDING`。缺少真实服务或设备时填写具体阻塞原因，不能把受控 fixture 的结果写成真实服务验收通过。

每条记录至少包含：case_id、应用版本、Git SHA、是否包含未提交修改、执行命令或操作步骤、运行环境、输入、预期、实际结果、run/task/operation ID、证据相对路径、时间、状态。

源码检查、单元测试、API 集成、浏览器交互、Tauri 窗口、外部模型、真实设备、安装发布分别记录。某一级 PASS 不能替代另一级。

证据拟存放在仓库内 `artifacts/v1-major-update/`，先检查 .gitignore；不要把密钥、用户文档原文、聊天隐私或大二进制误提交。文档索引保存脱敏摘要与证据路径即可。

### 3.1 重复回答的行为测试示例

本例是测试规格伪代码，不是已有可调用 API helper：

```text
准备：受控模型首轮仅返回 ask_user，问题选项 A/B；工具副作用计数=0。
发送：POST /api/chat，记录 run_id 与 question_id。
确认：run=waiting_input；数据库问题=pending；副作用计数=0。
并发发送：两个相同 expected_revision 的 answer 请求。
断言：一个 202、一个 409；数据库只有一份答案；原 run 仅续接一次。
让模型继续：返回一个写入受控文件的工具调用，授权按现有网关处理。
断言：最终文件 hash 正确；副作用计数=1；run_id 没变。
```

### 3.2 压缩与分支隔离示例

```text
准备：祖先消息含约束“输出使用中文”，分支 A 新增“只分析 A 文件”。
触发 A 压缩：摘要引用 A 的 through_message_id。
从 A 约束之前的祖先节点建立分支 B。
断言：B 的模型请求含祖先中文约束，不含 A 文件约束，不引用 A 的摘要。
断言：A 的原始消息仍可读取；B 的工具调用结果配对完整。
```

### 3.3 调度重启与错过示例

```text
准备：时区 Asia/Shanghai，每日 09:00；应用 08:59 退出，09:05 启动。
断言：当天 occurrence=missed；没有模型调用；next_run_at=次日 09:00。
用户点击现在运行：创建 manual occurrence，启动一次正常运行。
运行中再次到期：下一 occurrence=skipped_busy，原运行没有被替换。
```

## 4. 实施后检查命令

以下命令供后续实际开发完成时执行；本次只写文档，没有执行这些产品检查。

后端工作目录：仓库内的 `backend/`。

```powershell
cargo fmt
cargo fmt --check
cargo check
cargo test --test v1_major_chat_lifecycle --test v1_major_context --test v1_major_knowledge_memory --test v1_major_code_learning --test v1_major_automation --test v1_major_upgrade

```

前端工作目录：仓库内的 `frontend/`。已有依赖时不重新安装；依赖确有变更时使用与仓库锁文件一致的安装命令。

```powershell
npm.cmd run test
npm.cmd run build
npm.cmd run test:e2e
node e2e/core-paths.mjs --v1-major-update
```

最后一个命令是**拟新增验收入口**，必须在 core-paths.mjs 注册 `--v1-major-update` 并调用 v1-major-update.mjs 后才可执行。当前 `test:e2e` 的默认参数是 workbench-revision6，不覆盖本文全部功能；不得把现有 E2E 通过写成新增场景已通过。

根目录 Windows 打包使用已有命令：

```powershell
npm.cmd run build:windows
```

构建结果应是零退出码，警告单独记录。设备和安装用例需要实际操作证据；缺少模型凭据、LSP 程序、浏览器或音频设备时记录具体条件，不擅自安装全局软件或借用未授权账号。

## 6. 整体交付判断

M01–M17 的必选用例全部通过、构建通过、旧数据升级通过，并取得真实模型、浏览器、语音、文档程序、各渠道和 Windows 安装验证，才可标记此次 v1 更新完整交付。R2 的 A39–A60 同样属于完整交付条件，不以预览图代替运行测试。

如果只完成代码或受控用例，交付说明必须明确列出未验收项目及原因。不能删掉未通过的必选用例来宣称“一步完成”，也不能将未执行测试改写成“预计通过”。

文档本身的验收仅检查：参照来源可追溯；现状与拟新增分开；现有页面全部有落点；接口、状态和数据归属自洽；无开发周期；没有未授权子智能体或防御性开发安排。

R2 新增测试落点拟为 `backend/tests/v1_major_conversation_actions.rs`、`v1_major_media.rs`、`v1_major_artifact_versions.rs`、`v1_major_channels.rs`，以及 `frontend/src/features/conversation/conversationActions.test.tsx`、`frontend/src/features/creation/artifactVersions.test.tsx`、`frontend/src/features/channels/channels.test.tsx`。受控协议测试与真实渠道测试分别记录；全量 cargo test 包含新增文件，浏览器 `--v1-major-update` 覆盖新的页面与交互。
