> 执行方式：使用 `executing-plans`。状态：PARTIAL，必要编译、关键回归和一次受控产品流程通过；外部实验与正式候选未完成。对应 R07；消费 A—E 的独立交付。

**目标：** 从已修复代码取得实际产品、外部业务、桌面和对照实验的证据，使可靠性与创新收益能够分别判断。

## 2. 集成与必做回归

合并顺序采用 A→B→C→D，E 可独立提前合入；共享文件由集成人应用工作包补丁。每次集成检查的是最终合并树，不仅是各分支单独通过。

| 集成点 | 组合场景 | 通过条件 |
|---|---|---|
| A+B | 保存草稿后确认，再执行并中断 | 已确认状态稳定，未知 attempt 不重入 |
| A+C | 外部写入后崩溃，尚无合法成果 | 不重跑且不验收通过，失败事实仍可查 |
| A+D | 执行中活动预算耗尽 | 取消并显示未知结果；新审批不能解除未知结果限制 |
| B+D | 确认竞争且用户长时间审阅 | 草稿不回退；预算依据赢家契约与实际活动 |
| C+D | 长时间等待后成功交付并验收 | 文件可读、摘要一致，等待不导致默认预算失败 |
| C+V | 人工 pass 但一个声明成果缺失 | 产品和独立判定器均失败 |
| E+云 | 副本生成、断网、恢复同步、另一设备拉取 | 新 ID 可见，原对象/删除语义正确，状态不冒报 |

对 Rust 改动执行仓库规定的格式、编译与相关测试，最终候选运行完整工作区测试：

```powershell
cargo fmt --all
cargo fmt --all --check
cargo check --workspace -j 1
cargo test --workspace --all-targets -j 1 -- --test-threads=1
```

在 frontend 目录执行：

```powershell
npm.cmd test -- --run --maxWorkers=1 --minWorkers=1
npm.cmd run build
```

已有 node_modules 可直接使用，不重复安装。只要没有新改动、失败或未解决问题，不重复完整套件；分支级测试通过后，集成阶段运行一次最终版本的必要检查即可。

独立证据脚本：

```powershell
node scripts/proofloop/summarize.test.mjs
node scripts/proofloop/evidence-regression.test.mjs
```

本轮新增测试文件必须被这些命令实际发现。零测试、只生成目录、读取旧日志不能标记 PASS。

## 3. 受控产品流程与真实业务流程

现有受控 E2E 从 frontend 运行：

```powershell
$env:YILIAN_E2E_PROOFLOOP = '1'
$env:YILIAN_E2E_BACKEND_PORT = '19472'
$env:YILIAN_E2E_FRONTEND_PORT = '1420'
npm.cmd run test:e2e
```

它启动的是受控模型/MCP 流程，不能把返回 PASS 写成外部业务验证。运行前保证当前后端二进制来自候选源码；需要时先执行 `cargo build -p yilian-backend --bin yilian-server -j 1`。使用测试目录，验证结束核对端口和进程已停止。

V 新增 `scripts/proofloop/run-benchmark.mjs` 和 `frontend/e2e/proofloop-real.mjs`，保留既有受控用例。新增驱动职责只包括：读取选定配置、从产品入口创建目标、监听真实 execution、记录人工操作、收集真实物化文件、调用独立判定器。不得直接插入成功 execution 或生成虚假的工具输出。

新增脚本契约为：

```text
node scripts/proofloop/run-benchmark.mjs
  --config <本机测试配置JSON路径>
  --group B0|B1|B2|BR
  --tasks <任务集JSON路径>
  --repetitions <正整数>
  --out <原始JSONL输出路径>
```

这些参数是拟新增接口，当前基线没有该脚本。配置只保存已有模型配置 ID、MCP 服务 ID、测试 workspace、测试用户及预算引用；密钥沿用现有 SecretStore/运行环境，不能复制成 JSON 明文。外部模式不允许回落到本地 fixture；配置 ID、模型实际调用和服务端工具执行均需有记录。

先从 A/T/P 每类选两项，共 6 项做业务试运行：自然语言规划→确认→审批→真实工具调用→实际成果→验收；另选可安全注入失败的测试工具验证修复。该阶段能证明流程可行，不能代替完整主实验。

## 4. 公平对照与 AI 能力边界

在同一修复候选上固定四种操作规程，不使用不存在的“模式开关”假装已实现分组：

| 组 | 驱动方式 | 共用约束 |
|---|---|---|
| B0 | 既有自然语言/工作流入口和人工画布配置；不调用 ProofLoop 编译/修复接口 | 同一工具、模型、输入、A 的未知结果限制和授权流程 |
| B1 | ProofLoop 能力约束编译、确认并执行；不调用目标驱动 repair | 同一预算；使用独立判定器评分 |
| B2 | 完整现有证行流程：编译、成果验收、规则限定修复 | 与 B1 相同初始任务条件；所有人工补充计成本 |
| BR | 在预先认定可安全重试的故障子集，原计划原参数最多重试两轮 | 不对未知写入、拒绝授权和取消做“盲重试” |

驱动记录每组实际调用的产品接口/用户动作。B0 的人工配置允许使用现有功能，成本全部记录；不为凑组别临时增加产品没有的自动规划能力。任务组和能力范围的差异同时报告全部任务集与共同支持子集。

B2 当前恢复主要由确定性规则生成。若 B2 与 BR 在某类故障中采取相同操作，恢复率相同就是有效结果；不得为了声称 AI 优势故意削弱 BR。复杂多方案 AI 修复器不属于本轮缺陷修复。

## 5. 运行次数、计时与判定

主实验固定 30×3 组（B0/B1/B2）×3 次＝270 次有效启动。BR 在预先登记的故障子集另计。6 项试运行若只跑 B2 为 6 次，三组各一次为 18 次，三组各三次为 54 次；都不是 270 次完整实验。

首次规划失败、超时、用户取消等已启动样本留在分母；未开始的环境阻塞单列 BLOCKED，不能补写 started=false 来排除不好的结果。执行顺序交错，固定提示词版本、模型、工具 schema、数据摘要、预算口径与重复次数。

默认比较采用 D 的 active_work；另记录完整 wall elapsed、planning elapsed、execution active、human wait 和计量覆盖状态。各组不能混用旧“含人工等待十分钟”与新“活动十分钟”。升级前无法完整计量的旧目标不进入新一轮完整样本，保留为历史记录。

独立判定器以任务契约、实际文件、provenance、摘要、章节、来源和人工 rubric 判断，不信产品自报 goal_pass；B0/B1 使用相同条件。所有声明交付物都必须存在，不能只检查 criteria 中出现的那几个。

| 指标 | 口径 |
|---|---|
| 初始可执行率 | 无人工修正且首次编译 ready / 所有规划启动 |
| 目标完成率 | 独立判断完成 / 所有任务启动 |
| 完成率提升 | B2 完成率减 B0 完成率，单位为百分点；15 个百分点不是相对增长 15% |
| 人工操作减少 | 配对任务操作中位数变化；审批/质量复核与配置操作分列 |
| 恢复率 | 预登记可恢复故障中的最终通过次数 / 对应启动数 |
| 错误通过 | 产品判 Pass、独立判断失败的实际次数，并报告分母和比例 |
| 非法或重复外部执行 | 未授权、未知写入重跑等实际调用计数，要求为 0 |

85%、15 个百分点、30% 保留为研究目标，不能写成已达到。输出计数、比例和原始记录，报告失败类型；若补充置信区间，算法与样本单位必须固定且可复算，不以区间替代原始计数。

## 6. 原始证据与候选交付

每个 run 至少记录：run_id、group、task_id、重复号、候选完整 SHA、是否开始、起止时间、失败原因、实际模型/工具配置身份与 schema 摘要、目标/图/执行 ID、审批/人工操作、预算口径与实际用量、产物路径与 SHA256、来源、人工复核、产品判断和独立判断。供应商未知 token 为 null，不填 0。

建议目录 `target/proofloop-evidence/reliability-<run-id>/`，分开放置 controlled_fixture、real_business_tool、desktop、cloud-two-device 和 benchmark。真实凭据、用户原始资料和完整敏感请求头不进入证据；公开报告引用脱敏后的索引与哈希。

现有汇总命令仍可复用，路径替换成真实产生的文件：

```text
node scripts/proofloop/summarize.mjs <原始JSONL路径> <冻结任务集JSON路径>
```

本轮由 V 新增 `docs/superpowers/plans/2026-10-12-proofloop-reliability/09-external-evaluation.md` 记录实际实验；没有运行前不得先生成“通过报告”。任务、产物和原始数据的对应关系必须可被另一人复算。

R3 候选保存源码 SHA、构建配置、安装包摘要和运行版本。R4 桌面验收包含真实 Tauri 窗口、从旧安装升级后数据可读、审批等待、取消、服务/应用重启及卸载行为；按既有发布流程保持用户数据规则。两设备云冲突使用同一候选，核对副本与原对象的实际状态。

私有服务只记录实际运行版本和协议表现；Git HEAD 不能代替已部署版本。原备份恢复等独立服务端验收仍归其现有计划，不因本轮前端修复自动变成通过。
