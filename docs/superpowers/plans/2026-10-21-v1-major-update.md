## 1. 更新目标与边界

将现有的对话、画布、工作空间、能力、智能体、记忆、知识库、设置、语音和执行记录连接成可持续工作的桌面 Agent：用户提出目标后，系统能使用实际绑定的模型和能力，获得必要资料，执行任务，等待用户补充或批准，展示真实成果，并在后续对话中保留必要上下文。

本次“v1”指现有 Task World 产品主线。仓库包版本仍为 `1.1.0-rc.1`，同时已有 v1.2 开发资料；本文不把版本号回退成 `1.0.0`，也不擅自宣布新的正式版本号。发布时必须统一根目录、前端、后端、Tauri 和锁文件中的实际版本，并记录发布 SHA。

### 1.1 必须实现的产品结果

1. 一段对话在主页、消息画布、执行侧栏、日志和语音入口中具有一致的身份、运行状态和结果。
2. 已有“聊天／工作／创造”继续可用；增加代码协作和资料学习的场景预设，直接复用现有工作空间、知识库与能力体系。
3. 长对话压缩配置真正作用于模型请求，工具长输出可回读，压缩不会删除原始历史和已确认约束。
4. Agent 能提出结构化问题并等待回答，等待用户期间不继续执行后续动作。
5. 任务成果有文件、来源和验证记录，用户能预览、下载、定位和再次使用。
6. 记忆能够展示来源、作用范围、停用和替代关系；知识问答能够定位到被引用的原文。
7. 代码任务支持文件阅读、修改差异、诊断和实际验证；学习任务支持基于资料的笔记、练习与进度记录。
8. 用户能够创建本地定时任务，查看触发记录，暂停与取消；主动提醒严格按照用户配置工作。
9. 模型、基础服务、MCP、技能、工作流、插件的设置、发现、绑定、执行和停用行为一致。
10. 所有新增能力适配已有页面及昔涟主题，并用真实桌面、浏览器、文件和 API 证据验收。
11. 会话支持搜索、编辑后分支、重新生成、附件与导出，所有操作保留来源关系。
12. 创造模式覆盖图片、文稿、办公文档和成果版本，资料读取覆盖扫描件与演示文稿。
13. 角色与用户偏好在文字、语音和已启用渠道间保持一致，用户可以明确控制记忆与提醒。
14. 补充外部渠道配置、收发与会话归属规格；区分桌面资源连接器和消息渠道。
15. 首次配置、首次成功任务、应用退出、升级、数据导出与恢复形成完整产品流程。

### 1.2 架构决定

采用“在现有运行时和页面内补齐”的方案。保留 React、TypeScript、Zustand、Tauri、Rust、Axum、Tokio、SQLite；沿用 ReAct、SecurityExecutionGateway、TaskGraph、Workflow、ProofLoop、Resource 和现有事件体系。

曾比较的两种替代方案：仅增加页面按钮无法解决状态与数据闭环；复制 Cyrene 的 Electron、Node 插件宿主和整套 Harness 会引入第二套核心。因此不选这两种方案。

本次功能内部可以按依赖顺序实现，但所有必选模块必须一起达到交付标准。“一步完成”不意味着跳过构建、真实交互验证或把未完成模块写成后续再做。

## 3. 统一用户流程

### 3.1 普通工作与成果交付

用户在主页选择工作空间和场景，发送目标与文件 → 后端解析本轮实际绑定 → 展示必要澄清或目标计划 → 执行工具 → 用户批准需要审批的操作 → 观察与验证 → 在回复中给出成果卡、引用和未完成项。

简单问答不强制创建 TaskGraph。用户明确提出多步骤成果目标时，使用已有 ProofLoop 规划、计划审阅、验收与修复入口。普通对话产生文件也应注册 Resource/Artifact 关联，但不能因此伪造一张已验收的目标报告。

### 3.2 浏览器研究与文档制作

用户选择工作模式、绑定可用浏览器能力 → 查询并读取页面 → 将实际观察到的来源和截图登记为证据 → 生成文档并注册产物 → 检查文件存在、内容与目标要求 → 用户从当前对话打开文件。

浏览器返回“点击提交成功”只能说明动作发生；业务成功必须依据后续观察。右侧展示来自 adapter 的真实页面信息和截图，不用静态截图冒充可操作的嵌入浏览器。

### 3.3 代码协作

用户在工作空间选定真实目录 → 选择“代码协作”预设 → 读取文件、Git 状态和诊断 → 形成修改 → 查看修改前后 diff → 执行项目实际验证命令 → 显示退出码和日志 → 用户显式触发暂存、提交或推送。

提交和推送分别是独立操作，不因生成代码、完成任务或通过测试自动触发。不得自动清理用户修改、切换分支、创建备用实现或重写 Git 历史。

### 3.4 资料学习

用户导入资料或选择已有文档集合 → 选择“资料学习”预设 → 回答带原文定位的解释 → 生成可编辑笔记与练习 → 用户提交答案 → 记录本次结果与错题 → 用户按需创建复习提醒。

学习预设属于通用资料处理，不把专业教育 Agent 嵌入 Core。练习准确率只能由已提交答案和评分记录计算，不能用“阅读完成”推断掌握程度。

### 3.5 定时任务

用户填写时间、目标、工作空间、可用能力和通知位置 → 预览下一次触发时间 → 保存并显式启用 → 到时建立正常任务/会话运行 → 结果进入执行记录 → 点击通知回到对应运行。

任务执行中遇到高风险动作，进入已有审批流程；等待批准期间不能在后台绕过权限执行。关闭应用时不承诺任务仍会运行。

## 4. 现有页面适配规格

页面入口以当前 `WorkspaceSurface.tsx` 为准。不能因为磁盘上存在旧组件，就假定它仍有一级路由。设置页实际入口是 `SettingsCanvasPage`，能力中心当前使用分类入口和管理弹窗。

| 现有入口 | 保留内容 | 本次加入的交互 | 数据与导航要求 |
|---|---|---|---|
| `/chat`、`/chat/:id` | 会话侧栏、输入框、过程卡、执行侧栏 | 场景预设、目录/资料范围、待回答卡、引用、成果卡、上下文占用 | 以 conversation + run 定位；切换会话后不显示前一会话状态 |
| `/connectors` | 全部对话画布、所属智能体画布、消息分支 | 运行标识、引用/成果跳转、分支继承说明 | 布局改变不创建任务；分支调用普通 chat runtime |
| `/workspaces`、`/workspaces/:id` | 目录资料和任务列表 | 会话入口、文件列表、Git/诊断/验证/定时任务页签 | 所有操作使用当前 workspace_id，不读取另一目录的缓存 |
| `/capabilities` | Skill、工作流、MCP、工具、插件、导入分类 | 真实可用范围、使用记录、配置跳转、定时入口 | 沿用 category 查询参数，不复制第二个能力目录 |
| `/agents` | 角色、用户提示词、能力绑定 | 默认场景、默认资料范围、实际生效配置摘要 | 不把角色文案当作权限授权 |
| `/memory` | 搜索、分类、来源、编辑与删除 | 启用/归档、替代关系、来源定位、作用范围、最近使用 | 文档派生片段继续有文档关联，不混入用户偏好 |
| `/knowledge` | 导入、全文、检索、原文件下载 | 文档集合、引用定位、学习会话、笔记与练习 | `document` 查询参数继续支持；新增定位参数不覆盖选中文档 |
| `/settings` | 设置画布、节点管理、编辑对话框 | 场景配置、实际模型能力、压缩效果、提醒策略 | 使用现有 section 打开编辑器；节点可见性与功能启用分开 |
| `/system` | 资源、服务与 token 信息 | 等待/运行计数、上下文统计、调度状态 | 指标必须来自实际记录，估算与供应商 usage 分开 |
| `/logs` | 系统日志、工具记录 | 按 run、会话、工作空间、定时触发过滤 | 从日志可回到原对话/任务，导出脱敏 |
| `/more`、插件功能页 | 非一级导航和插件贡献入口 | 定时任务汇总入口、已有声明式扩展贡献 | 新入口仍使用 PageShell，不另造整套导航 |
| `/account`、`/setup` | 身份、同步、隐私、首次配置 | 检查新增本地数据是否纳入导出和删除说明 | 不扩展私有云协议；本次新增数据默认仅本地 |
| 全局语音与悬浮窗口 | 会话锚点、通话/停止操作 | 待回答提示、结果通知、与文字共用运行状态 | 输入源切换不会建立两次任务或重复发送识别文本 |

### 4.1 布局与视觉

- 保留当前昔涟主题、ThemeProvider、applyTheme、tokens 和已有组件，不新增独立主题系统。
- 保留主页 `1180/960` 宽度分界及既有抽屉语义；在窄窗口中，资料、成果、Git 与执行详情使用同一侧栏容器的页签。
- 对话正文保持连续；执行过程、引用和详情可展开，避免每一步都弹出模态框。
- 用户提出问题的输入框、发送和停止始终可达。新卡片不挤出输入区，不与语音浮层遮挡。
- 显示“未配置、正在执行、等待回答、等待批准、已完成、已取消、执行失败、结果待确认”等具体状态；不要只依赖颜色。
- 初次空页面给出真实的下一步入口；请求失败显示原因及用户可触发的重试，不伪造示例数据或自动切换服务。
- 设置保存与下一轮生效要清楚区分；当前运行使用的模型、资料范围与能力快照可在详情中查看。

### 4.2 R2 简洁界面规则

- 首次进入主页默认只展开导航与对话。会话历史通过“对话”按钮打开，允许用户固定；右侧详情默认关闭。1180/960 分界保留，但不再强制宽屏首次打开会话列表。
- 输入框默认仅保留附件、一个模式菜单、语音与发送。模型、场景、工作空间、资料范围放入同一个选择面板；只有用户选定附件时显示附件条。
- 正常执行只显示一句进度及停止按钮；过程点击展开。完成后停止按钮消失，文件结果以紧凑文件行呈现。
- 普通回答不展示任务面板、token 占比、资料数量和验收术语。工具有副作用时仍在实际操作前显示既有必要审批。
- 提问仅在缺少执行必需信息时出现；默认不是每次任务都要求用户确认交付范围。
- 画布、设置、知识库、能力等页面保留业务结构，各页面最多一个主要操作；高级编辑器与详情按需打开。
- 图片只是页面样式和示意状态。准确路由、文案、协议与功能完成状态以开发契约和实际验收为准。

### M01：运行身份、过程与恢复视图

**拟新增：** `backend/src/db/chat_runs.rs`、`backend/src/api/chat_runs.rs`、`frontend/src/api/chatRuns.ts`。

- [ ] 一次用户输入创建一个 run_id；审批后继续、回答澄清后继续沿用该 run_id。
- [ ] 记录起止时间、实际模型、工作空间、场景、绑定版本与本轮用户消息 ID。
- [ ] 给本轮 SSE 增加 run_id 和顺序字段；既有事件名与字段含义不改变。
