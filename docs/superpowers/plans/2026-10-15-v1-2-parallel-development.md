**目标：** 对齐用户提供的《忆涟千言下一阶段发展规划：修复与创新迭代双线并行》，在已有证行引擎上提高能力选择、计划质量、经验复用和实际成果交付能力，并完成可复算的自动化验收。

**架构：** 继续使用 TaskGraph、Task Harness、Capability Registry、现有审批网关、记忆转技能、任务检查点与 SQLite。增加排序、候选计划比较、目标视图和有限执行适配器；执行事实和成果状态仍由原有系统产生。

**技术栈：** Rust / Axum / Tokio / rusqlite；React / TypeScript / Vite / Zustand；Tauri。浏览器扩展采用独立 Node / Playwright MCP 提供方，Rust 仍是主后端。

## 1. 先读结论

这份计划分为六个验收阶段和十四类工作责任，阶段不是串行开发清单。P0 冻结后，R 线回归、能力路由、计划评分、目标视图、经验推荐、检查点展示、修复提案、浏览器适配器和评测准备都可以启动；真实接线按依赖进入 G1–G4。

本轮源码核对发现，报告中的五项修复已有当前工作区实现，必须先复验，不应再次重写。工作区存在 19 个既有变更，尚未形成可共享的干净提交。当前分支为 `fix/proofloop-review-oct13`，HEAD 为 `71883f00402795bb78d4f98e4ac94583bc7383a0`。HEAD 本身不能代表本次看到的全部代码。

当前产品版本字段仍为 `1.1.0-rc.1`；“v1.2”是规划名称，不代表已发布。本文所有新功能、业务实验和发布门槛初始状态均为 `NOT TESTED`。

## 3. 阶段和可同时开展的工作

| 阶段 | 退出成果 | 可以提前开发 | 真实集成前置 | 门槛 |
|---|---|---|---|---|
| P0 基线与契约 | 共同基线、DTO、夹具、所有权、任务集冻结 | R 复现、E 任务审计、协议资料核对 | 不依赖新产品功能 | G0 |
| P1 智能规划闭环 | 目标→排序→2–3候选→确认→原 Harness 执行 | U 目标视图、X 推荐、K 档案、F 修复纯逻辑、B 浏览器本地服务 | G0 + A/B 核心接线 + R 必需回归 | G1 |
| P2 工作台与经验 | 双视图、真实文件交付、已审核技能推荐、检查点说明 | F/B/D/M 继续各自集成与测试 | U/X/K + G1；格式能力逐项验收 | G2 |
| P3 恢复与浏览器 | AI 修复在预算内起效，浏览器测试站操作有证据 | D 交接、M 外部协议仍可独立推进 | F 依赖 R+G1；浏览器独立 GB，不强依赖 X | G3 |
| P4 协作与实验候选 | 有限交接、单个外部智能体、资源上限、270次主实验 | 独立协议兼容测试、制品准备 | D/M 自身门槛；主实验仅依赖 G1/G2/F | G4 |
| P5 独立终审 | 范围明确的通过/未完成结论和证据索引 | 原负责人按问题单窄修复 | 对应范围所有必需项有证据 | G5 |

P4 的扩展能力不是主实验前置。浏览器和 ACP 尚未通过时，可以完成并审查核心规划产品，但不得称“八项全部完成”。P0 后的最短核心路径是 A→B接线→U接线→G1；X、K、R和E与其并发。
