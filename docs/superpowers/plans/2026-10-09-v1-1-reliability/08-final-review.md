# S8 最终独立审查与发布结论

> 本阶段必须最后执行。状态：NOT STARTED。这是一轮新的正式审查，不是把开发者测试摘要重新抄写一遍。

## 1. 审查输入和独立性

输入必须包括：公共/私有两个仓库的准确 SHA、S0 r2 契约与 fixture 哈希、S1—S6 工作包交接记录、S7 证据包、migration/回滚设计、运行版本与安装包哈希、原审查报告 R01—R15、源码托管决策。

审查者原则上不承担被审模块的主要实现；可由其他开发者或用户指定审查人员执行。未经用户明确告知，不自动创建子智能体。单人自审只能标记 `SELF_REVIEW`，不能把它说成独立复审已完成。

审查者在独立目录/环境检出固定 SHA；不得改动冻结 V2，不以开发者日常 app-data 做破坏性测试。

输出文档建议为 PRIVATE `docs/reliability/final-review-2026-10-09-cycle.md`，日期以实际审查日更新；公共仓库只保留经过脱敏的发布结论与公共契约证据。

## 2. 四类审查内容

### A. 源码与契约审查

- [ ] R01：所有 download_cursor 写入口都追溯到已提交 pull 页；push ACK 无推进路径。
- [ ] R02：所有同账号数据写入口都在分配序号前获得相同 owner 锁；部署已排空旧事务。
- [ ] R03：旧版本在写业务表前退出；相等版本内容校验、业务镜像修复路径完整。
- [ ] R04：业务数据、资源、索引、前端缓存、SecretRef、在途回包全部遵循 profile 边界。
- [ ] R05：设备/会话复合归属约束存在且通过反向插入测试；refresh/revoke 竞态不复活会话。
- [ ] R06：冲突完整记录两侧操作；missing upsert payload 不允许解决；delete 语义保持。
- [ ] R07/R08：删除清单、租约、旧 worker 栅栏和最终扫描形成闭环；失败不报告 completed。
- [ ] R09/R10：退出远端状态真实；导出下载需认证、隔离 owner、具备到期与注销清理。
- [ ] R11/R12：类型化白名单、system 排除、策略关闭不产生 delete；插件使用记录来自真实执行。
- [ ] R13：损坏 grant 不被默认允许、忽略 deny 或弱化资源范围；安全网关仍 fail closed。
- [ ] 接口一致：字段/枚举、HTTP 错误码、状态机、单位、nullable、schema 版本在两端一致。
- [ ] 兼容性：旧客户端门禁、schema升级、恢复 epoch、关闭云功能的本地可用性均有清晰行为。

### B. 对抗性运行复核

至少独立复跑 E01、E02、E04、E05、E06、E08、E09、E11、E12、E13、E14、E17、E19、E20。其余用例可以审核可靠的 S7 原始证据，但必须能定位测试环境、命令和断言。

重点不要只看成功路径：让数据库事务等待、切断响应、终止测试 worker、模拟磁盘拒绝写/删、制造损坏授权、在账号切换期间恢复网络。实际文件清理和桌面呈现必须观察最终状态。

### C. 数据迁移与恢复审查

- [ ] 源库备份在真实 SQLite/WAL 情形下可恢复；归属不明数据不会自动绑定最后登录账号。
- [ ] 已有错属 session、旧高 cursor、running 卡住任务有处理路线。
- [ ] migration 可重复启动、校验版本和摘要；不会重用旧迁移编号或修改历史 SQL。
- [ ] 回滚不会把新库交给不兼容旧程序，不会丢弃用户未知写入。
- [ ] 备份删除保留期、派生对象覆盖面明确，恢复删除账本不会重新开放已注销账号。

### D. 交付与范围审查

- [ ] 公共客户端、API、worker、管理后台的实际运行版本与清单匹配。
- [ ] 安装包哈希对应本轮构建；首装、升级、卸载及数据保留路径有真实记录。
- [ ] 私有源码托管选择已确认；不存在私有源码、真实凭据、用户数据进入公共制品。
- [ ] 未修改冻结 V2，未引入无关重构，未移除审批/取消/循环保护。
- [ ] 文件夹整理未被误描述为删除或释放磁盘空间；历史工作区与未提交内容可定位。

## 3. 发现记录与回流

每个发现独立记录：

```yaml

severity: CRITICAL
status: OPEN

trigger: null
expected: null
actual: null
reproduction_evidence: null
required_fix: null
fix_commit: null
retest_evidence: null

```

正式发现必须填写触发条件、具体函数和可核查证据；证据不足标记“待验证风险”，不能编造事故。修复回原工作包提交；复审必须检出修复后的 SHA 再验证。

变更影响传播规则：

| 改动 | 必须重验 |
|---|---|
| 契约/字段/错误码 | 两端契约测试、所有直接消费者、至少一次真实联调 |
| owner锁/序号/幂等 | E01/E02/E10/E13/E18 |
| profile/会话/设备 | E05/E06/E07/E13/E14/E19 |
| 页面事务/版本/冲突 | E03/E04/E08/E09/E10/E19 |
| worker/清单/下载 | E11/E12/E13/E14/E20 |
| 采集/删除捕获/授权 | E15/E16/E17，另加受影响实体同步用例 |

## 4. 发布门禁

| 结论 | 条件 |
|---|---|
| PASS，可进入用户批准发布流程 | 全部严重/高问题关闭；R01—R15有处理记录；必跑实测通过；迁移、恢复、运行版本、安装包、托管决策齐全 |
| FAIL，退回修复 | 任一严重/高问题未解决，或测试证明数据丢失/混用/复活/虚假删除完成 |
| BLOCKED，证据不足 | 无法访问所需隔离环境、无法核验运行版本、无法完成恢复等；写明解除条件 |
| HUMAN_PENDING | 安装/卸载人工动作或源码托管/发布决定未完成；不能当作 PASS |
| NOT TESTED | 尚未执行，不能由历史测试数字替代 |

“受控本地演示可用”与“允许真实用户自动云同步/永久注销”是不同结论。若只有本地功能通过，应明确限制为本地使用，云端开关继续关闭。

本轮不允许用“低概率”“测试项总数很多”“代码已经合并”豁免数据隔离与永久注销的严重问题。中低风险如接受延期，必须有责任人、明确影响、补救措施和下一审查日期。

## 5. 最终报告格式

1. 审查日期、人员与独立性；两仓库 SHA、运行版本、安装包哈希。
2. 总体结论：PASS/FAIL/BLOCKED/HUMAN_PENDING，以及允许开放的实际范围。
3. R01—R15 逐项：代码位置、修复提交、独立复验、最终状态。
4. 新发现和剩余问题：严重性、复现条件、影响、责任工作包。
5. 数据迁移/备份/恢复/账号注销覆盖范围及限制。
6. 原始证据索引和脱敏说明。
7. 用户发布决定记录；没有决定时不能替用户写“已批准上线”。

- [ ] S8.1 收齐证据并固定审查提交，不使用浮动分支 HEAD 作为唯一标识。
- [ ] S8.2 完成源码/契约审查与必跑场景复验。
- [ ] S8.3 回流问题、核验修复提交并按影响矩阵重验。
- [ ] S8.4 给出明确发布结论与范围，保留仍待人工完成的项目。

建议文档分支：`docs/v1-1-final-reliability-review`。没有运行证据时只能交付审查计划，不能生成预设 PASS 的正式审查结论。
