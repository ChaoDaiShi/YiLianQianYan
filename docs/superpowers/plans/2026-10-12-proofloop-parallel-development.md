# 忆涟千言证行引擎多阶段并行开发方案

> 日期：2026-10-12。性质：开发计划，尚未实施。
>
> 执行方式：按工作包逐项实施、逐项验收；可由多名开发者或用户明确启动的独立会话并行承担。本方案不授权自动使用子智能体，也不授权提交、推送、合并或发布。

**目标：** 在现有 Task World 中实现“自然语言目标 → 真实能力编排 → 类型化执行 → 成果验收 → 有限修复”，使研发和科研任务能够交付可核查成果。

**架构：** 复用 TaskGraph、Capability Registry、Task Harness、SecurityExecutionGateway、U3.1 类型化绑定、审批和执行历史。新增部分只负责候选计划编译、目标级验收、修复提案及现有产品界面的连接。

**技术栈：** Rust / Axum / Tokio / SQLite，React / TypeScript / Vite / Zustand，Tauri；保持现有 SSE、资源授权与取消机制。

## 1. 本轮决策与范围

推荐采用“先冻结最小契约，再按能力、编译、验收、修复、界面、评测六条工作线滚动集成”的方式。按模块切分可减少文件冲突；按用户流程设置阶段门槛，可避免各模块完成后仍无法实际使用。

三种组织方式的取舍：

| 方式 | 优点 | 主要问题 | 本轮选择 |
|---|---|---|---|
| 完全按 I0→I1→I2→I3→I4 串行 | 管理简单 | 界面、验收与评测启动过晚 | 不采用 |
| 所有模块同时开工 | 看似并行度最高 | 契约、状态和共享文件反复冲突 | 不采用 |
| 契约先行，模块并行，产品分阶段验收 | 可独立测试，也能持续形成完整流程 | 需要明确集成负责人 | 采用 |

本轮应用场景限定为软件研发与科研创新中的资料分析、结构化工具协作、技术选型和实施计划。首个产品样例从一个两节点、真实 MCP 数据传递任务开始，随后扩展为可追溯调研成果；不一开始追求所有任务类型。

本轮不包含私有云端、管理后台、冻结 V2、桌面控制扩建、新的多智能体系统、长期经验学习平台、模型训练、通用安全框架、通用 JSON Schema 引擎及全局架构重写。成功经验反馈先用真实执行历史支持人工复用，不纳入首轮关键路径。

“禁止防御性开发”在这里指不为假想风险增设平台、权限层或复杂恢复系统。已有审批、权限、类型检查、取消与历史保留属于本功能的必要执行条件，继续复用。

## 6. 范围档位与工期假设

采用三个可独立说明的交付档位：

1. **I1 最小可交付档：** 真实自然语言规划、类型化 MCP 图、计划确认、保存重开、既有审批和执行；允许目标验收暂以明确列出的人工条件结束。
2. **I2 成果可验证档：** 在 I1 上增加目标契约、自动条件检查和人工确认项，交付成果与证据。
3. **I3 完整证行档：** 增加真实失败驱动的局部修复和再次验收；完成实验后才能宣称恢复能力提升。

资源估算采用 3 名熟悉仓库的开发者、已有可用模型与 MCP 环境的假设：I0 约 0.5–1 个工作日；I1 约 2–4 日；I2 约 1–3 日；I3 约 2–3 日；I4–I5 约 2–3 日。C/E/F 的提前开发可缩短关键路径，整体先按 8–14 个工作日安排；这是排期估算，不是交付承诺。

原报告提到的 **2026-10-13** 仅作为可选内部检查点，本次没有得到新的硬截止要求。如果仍采用该日期，检查范围应限于 I0 和 I1 的首条真实链路及小样本记录；未通过 G1 就交付契约和实际进度，不将完整 I1、I2、I3 写成完成。

## 7. 量化目标和比赛材料

研究指标采用用户建议：初始计划可执行率 ≥85%，完整方案目标完成率相对基线提升 ≥15 个百分点，人工配置操作中位数减少 ≥30%。异常恢复报告固定重试基线与完整方案的实际差异；非法/未授权真实执行次数为 0。所有数值均为研发目标，当前没有新实验结果。

创新主张限定为“真实能力约束、类型化任务编译、目标证据验收与有限修复的一体化工程机制”。Reflexion 已研究执行反馈与后续尝试改进，因此不宣称反馈学习本身由本项目首创。[Reflexion 论文](https://arxiv.org/abs/2303.11366)

比赛的创新性、技术实现、功能完整性、方案完整性分别占 20 分，应用价值占 15 分，总结与展望占 5 分。本方案以运行成果、原始评测记录、算法说明、使用/部署材料逐项支撑；这些权重不构成对本项目得分的预测。[AI+软件创新官方赛题与评分规则](https://www.aicomp.cn/tracks/tracks-2/3792.html)
