# 记忆网络：当前投影、版本空间和对应关系

现有 1040 治理表已保存正文修订、有效状态和来源引用。旧图谱直接读取当前记忆，结构化人物、事件、项目与概念关系只存于当前记录；旧版「纠正」即使内容完全相同也可能推进修订号。因此，历史层数不能从旧修订号简单减一。

- SQLite 迁移 1091 为版本补充来源与关系结构，保留现有表与修订号。图谱按同一条记忆可证实的变更，从层 0 向上计数；旧重复快照归到同一层，未知原始记录标为基线。迁移只记录可读取的当前关系，不用它回填旧关系。停用形成一条实际的状态变更；清除移除正文及版本。
- 1092 新增档案内记忆对应关系和对应关系历史。边以两端的逻辑 ID 连接，在保存修订时记录两端的真实版本 ID；边修订不推进记忆版本。普通边是对应关系，不视作触发或因果。关联纠正由用户提交到现有候选队列，确认时重新检查关联状态和目标修订，只实际更改目标一条；同内容不产生新版本。
- `GET /api/memories/graph` 从同一个 SQLite 事务读取当前节点、逐条历史和边历史。默认二维投影不读入无效节点或未确认关系，待确认有独立开关。已有类型视图保留。三维使用同一快照，以二维世界坐标作为 x/y、逐条记忆的真实层数作为 z；中键拖动改变相机角度，视角切换没有写操作。
- 删除来源只使来源不可定位；已留存记忆仍可按既有治理查看。彻底删除通过现有删除和重放入口清除快照、图边和相关待审阅正文。还原旧备份仍须保留比备份新的删除日志。图快照和额外关系结构留在当前档案，现有云协议不传输它们；未承诺旧备份物理擦除或生产云验证。

旧客户端不会使用新图 API。保留原版版本表及其 SQL 列顺序；降级期间缺少的历史结构只按实际记录处理。用户数据的备份恢复应同时保留更新的无正文清除日志。

本次验证边界：桌面验收由 `frontend/e2e/native-memory-space.mjs` 启动隔离 WebView2 和本地服务，使用真实 SQLite、合成业务记录、真实指针操作、合成失焦事件。覆盖亮暗主题、窄桌面窗体、36 条有效记忆、旧客户端降级读写再升级、SQLite 在线备份恢复和删除重放。索引重建通过真实本地接口发起，向量由回环夹具提供；云端工作限于本地协议投影和恢复集成测试。老版本客户端自身的重复纠正行为未改写。
