# 任务与能力管理可用性修复设计

## 目标

修复任务中心无法准确反映后台对话任务、状态筛选看起来无效的问题，并为技能、能力来源和 MCP 服务提供清晰、真实、可失败恢复的管理体验。

## 约束

- 不建立第二套 Agent、Tool、Capability 或 MCP 运行时。
- 不改变既有 SSE 事件名称和语义。
- 后台状态必须来自真实执行生命周期，不根据 UI 是否打开推断。
- Capability Registry 继续作为派生发现层，不允许创建没有真实执行来源的“假能力”。
- 技能写操作只允许落在工作区托管的技能目录内；外部配置目录保持只读。
- MCP 环境变量继续由现有 SecretStore 处理，前端不得回显秘密值。
- 不使用子智能体。

## 根因

### 任务中心

任务状态筛选只作用于 `tasks` 表记录，但页面顶部的对话记录始终显示且不参与筛选。聊天 Agent 虽然由后端 `tokio::spawn` 继续运行，工具事件也能在浏览器断开后持久化，但对话没有整体运行状态字段。因此离开对话后，任务中心无法分辨运行中、等待审批、完成、失败或取消，用户会认为任务没有在后台完成，切换筛选也没有作用。

### 技能

技能 API 只有列表和读取两个 GET 接口。技能页文案写着“管理”，但实际只能查看 `SKILL.md`。

### 能力

能力记录由内置 Tool、Skill、MCP、Agent 和 Workflow 等真实来源派生。直接给 Capability Registry 增删改会产生与真实执行器脱节的第二套状态。

### MCP

MCP 后端已有 CRUD、启停和连接测试，但前端主要使用弱可见的图标操作，通用 `request()` 会把 HTTP 错误吞成 `null`。保存或删除失败时缺少可读反馈，保存弹窗还可能在失败后关闭。

## 设计

### 1. 持久化对话任务生命周期

为 `conversations` 增加兼容迁移字段：

- `run_status`: `idle | running | waiting_approval | completed | failed | cancelled | interrupted`
- `run_error`: 最近一次真实运行错误，可为空
- `run_started_at`
- `run_finished_at`

聊天请求接受后将状态写为 `running`。真实的 `done`、`error`、审批暂停和停止操作分别更新对应状态。应用启动时将遗留的 `running` 状态标为 `interrupted`，避免重启后持续误报运行中。SSE 仍按既有事件发送。

对话摘要 API 只增加可选展示字段，不删除或重命名现有字段。任务中心把对话运行记录作为“后台对话任务”显示，并和任务表记录使用同一状态筛选语义。存在真实运行项时按固定间隔刷新；没有运行项时停止轮询。

### 2. 托管技能 CRUD

新增以下接口：

- `POST /api/skills`
- `PUT /api/skills/:name`
- `DELETE /api/skills/:name`

写入目标固定为第一个位于工作区内的配置技能目录，默认 `./skills`。名称拒绝空值、路径分隔符、`.`、`..`、控制字符和超长输入；内容拒绝空值和超过上限的输入。更新支持安全重命名和 `SKILL.md` 内容替换。删除前验证规范化路径仍位于托管根目录内，再删除整个技能目录。

列表响应增加 `editable`，外部技能仍可读取但不能编辑或删除。每次变更后重建现有 `SkillDiscovery` 并使 Capability Registry 缓存失效，使新技能立即进入 Agent 可见范围。

技能页提供新增、编辑、删除、保存失败反馈和删除确认。编辑器直接编辑真实 `SKILL.md` 内容，不发明版本、安装状态或测试结果。

### 3. 能力来源管理

能力页保留发现、筛选和详情职责，同时增加“新增能力来源”和“管理来源”：

- Skill → 技能页，并定位对应技能；
- MCP → MCP 服务管理页；
- Agent → 智能体页，并定位对应定义；
- Workflow → 工作流页，并定位对应流程；
- Builtin Tool / Subagent → 明确显示为系统提供、不可直接删除。

“新增能力来源”让用户选择新建技能、添加 MCP、创建智能体或创建工作流。CRUD 始终由真实来源页面及其既有 API 完成，Capability Registry 刷新后自然反映变化。

### 4. MCP 管理可用性

保留既有 MCP 数据结构和 SecretStore 流程。前端 API 改为结果类型，页面对创建、更新、删除、启停、测试、刷新分别处理错误。

服务器卡片展示带文字的“编辑”“删除”“启用/禁用”和“测试连接”操作，不再依赖用户猜测图标。表单严格校验名称、stdio 命令、Streamable HTTP URL、参数 JSON 和环境变量 JSON。请求失败时弹窗保持打开并显示可读错误，成功后才关闭并刷新列表。

### 5. 错误、安全与可访问性

- 普通错误区显示用户可理解的信息，技术详情不回显秘密值。
- 删除技能和 MCP 均要求明确确认。
- 所有新增操作按钮提供文本或 `aria-label`，保留键盘焦点。
- 后台状态不显示伪造百分比或预计时间。
- 路径验证失败时拒绝写入，技能删除遵循 fail-closed。

## 测试

- Rust：对话生命周期迁移与状态更新、异常恢复、托管技能路径校验、技能创建/更新/删除和发现刷新、MCP 错误响应。
- Frontend：对话状态到任务筛选的映射、运行时轮询条件、技能表单和 CRUD 交互、能力来源路由、MCP 失败不关闭弹窗及可见操作。
- 回归：完整 `npm test`、`npm run build`、`cargo fmt --all --check`、`cargo test --workspace`、`cargo check --workspace` 和 Tauri release check。

## 非目标

- 不让 Capability Registry 直接执行能力。
- 不新增通用自定义 Tool DSL。
- 不实现跨应用重启自动恢复尚未完成的 Agent 推理；重启后只真实标记为已中断。
- 不修改现有安全审批策略和 MCP 协议语义。
