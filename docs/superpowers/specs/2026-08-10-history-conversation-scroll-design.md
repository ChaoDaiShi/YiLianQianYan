# 历史对话滚动隔离修复设计

## 背景

在桌面工作台中选择一条较早且内容很长的历史对话后，页面会被滚动到整份文档底部。消息正文与输入框仍然可见，但顶部栏、左侧历史对话栏和右侧执行轨迹栏停留在文档顶部，用户无法通过当前视口返回或切换对话，控制台也不会产生错误。

本地只读数据检查确认，当前数据库中存在一条长度为 27,237 个字符的历史助手消息。该消息稳定触发长内容路径。

## 根因

2026-08-10 的工作台重构引入三栏 CSS Grid 后，滚动边界没有完整闭合：

- `.workbench-grid` 设置了 `height: 100%`，但没有将网格行限定为 `minmax(0, 1fr)`；
- 工作台主区域和聊天主列缺少一致的 `min-height: 0` 与溢出约束；
- 历史消息加载后，`ChatView` 对末尾锚点调用 `scrollIntoView()`；
- 当长消息把网格项目的自动最小高度撑大时，末尾锚点的滚动会作用到页面祖先，而不只作用于消息列表。

因此，这是前端视口约束与滚动目标共同造成的布局问题，不是历史数据损坏，也不是后端接口异常。

## 已确认行为

打开任意历史对话时：

- 默认定位到最后一条消息；
- 只有中间消息列表可以纵向滚动；
- 左侧历史对话栏、右侧执行轨迹栏、顶部栏和输入框始终留在当前视口；
- 不截断、不删除、不迁移历史消息内容。

## 方案比较

### 方案一：布局约束与定向滚动同时修复（采用）

闭合工作台的高度与溢出边界，并将自动滚动改为直接操作消息列表容器。

优点：同时修复根因和触发路径；未来出现其他超长内容时也不会再次撑开整页；滚动目标明确。

代价：需要在工作台、聊天列和消息列表之间传递一个滚动容器引用。

### 方案二：仅补充 CSS 高度约束

优点：代码改动最少。

缺点：`scrollIntoView()` 仍然可能滚动祖先容器，滚动行为依赖 DOM 与浏览器实现，边界不够明确。

### 方案三：仅替换 `scrollIntoView()`

优点：直接消除当前自动滚动整页的触发点。

缺点：没有修复网格项目的自动最小高度，其他长内容仍可能把工作台撑出视口。

## 详细设计

### 视口边界

工作台外层继续使用现有三种宽度模式，不改变列宽与响应式行为。

需要建立以下纵向约束：

1. `AppShell` 的主内容区域可以收缩，并隐藏工作区之外的溢出；
2. `.workbench-grid` 使用单行 `minmax(0, 1fr)`，同时设置 `min-height: 0` 和 `overflow: hidden`；
3. `ChatView` 的主聊天列设置 `min-height: 0` 和 `overflow: hidden`；
4. `MessageList` 保持 `flex: 1` 与 `overflow-y: auto`，成为聊天区域唯一的纵向滚动容器。

### 自动滚动

`MessageList` 将自己的根滚动元素通过引用暴露给 `ChatView`。消息或流式内容更新后，`ChatView` 直接调用该元素的滚动 API，将其滚动到 `scrollHeight`。

不再通过末尾锚点的 `scrollIntoView()` 触发祖先滚动。滚动容器尚未挂载时，该操作安全地跳过，不抛出错误。

### 数据流

历史对话加载流程保持不变：

```text
选择历史对话
  -> 路由切换到 /chat/:id
  -> loadConversation(id)
  -> setMessages(messages)
  -> 消息列表渲染
  -> 仅消息列表容器滚动到底部
```

后端响应、消息结构、旧版 `tool_calls` 兼容逻辑和执行轨迹水合逻辑均不改变。

### 错误处理

- 滚动容器引用为空时不执行滚动；
- 历史会话加载失败时沿用现有行为，本次不扩展错误界面；
- 不读取、重写或删除数据库中的历史消息；
- 不引入新的前端依赖。

## 测试设计

先建立失败回归测试，再实现修复。

自动化验证覆盖：

- 自动滚动调用消息列表容器，而不是窗口或末尾元素的 `scrollIntoView()`；
- 工作台布局契约包含纵向收缩和溢出隔离所需约束；
- 现有响应式宽度模式与抽屉状态测试继续通过；
- 全量前端 Vitest 测试通过；
- TypeScript 与 Vite 生产构建通过。

浏览器级验证使用超长历史消息场景，检查：

- `window.scrollY` 保持为 `0`；
- 消息列表的 `scrollTop` 接近 `scrollHeight - clientHeight`；
- 顶部栏、输入框和宽屏左右侧栏都位于视口内；
- 可以从左侧栏切换到其他历史对话或新建对话。

## 范围限制

本次不包含：

- 历史消息截断、分页或虚拟列表；
- 数据库迁移或历史内容清理；
- 三栏视觉样式、列宽或响应式断点调整；
- 后端会话 API 改动；
- 与滚动故障无关的组件重构。
