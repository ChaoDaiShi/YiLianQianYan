# YiLianQianYan v0.8.0 Release Notes

## Added

- A frozen release boundary for trusted tool execution, resource grants, and desktop packaging.
- Server-created authorization evidence for network zones and managed process controls.
- Release-gate evidence checklist covering build, migration, SecretStore, isolation, MCP, and desktop lifecycle checks.

## Security

- Process authorization is limited to Agent-managed children. Explicit PID and all-host legacy grants are readable for migration but fail closed at execution.
- Network requests use one DNS resolution, pinned addresses, no proxy, no redirects, and trusted gateway-created zone evidence.
- Runtime security audit events preserve the initiating subject ID across policy, approval, execution, grant, and verification phases.
- The RC acceptance used a real Windows Credential Manager profile with write, rotate, restart-read, clear, and zero-plaintext sentinel checks.

## Windows packaging

- The v0.8 Windows target is the NSIS installer: `忆涟千言_0.8.0_x64-setup.exe`.
- MSI is not selected for v0.8 because the current WiX path cannot encode the Chinese product name with its active database code page.
- The Vite bundle-size warning is recorded as a v0.9 performance follow-up; no code-splitting refactor is included in this release candidate.

## Dependency audit

- `npm audit --omit=dev` reports five moderate production findings across React Router and the syntax-highlighter/PrismJS chain. The affected packages are present in the production bundle; available fixes require major upgrades. They remain a documented v0.8 known risk and are deferred to a dedicated v0.9 dependency-upgrade item.
- `cargo-audit` was installed, but the RustSec advisory database could not be fetched in this environment because the Git/Schannel connection failed. No Rust advisory result is claimed.

## Known boundaries

- The application-layer isolation controls are not claimed to be a complete host sandbox.
- There is no OS filesystem namespace, OS network namespace, restricting-SID ACL sandbox, GUI sandbox, or container-grade sandbox in v0.8.
- Process control is limited to Agent-managed children.
- Upgrades should be performed after a user-data backup; v0.8 does not claim safe downgrade support after migration.
- A release is not considered ready until the real packaged Windows Tauri launch, visible frontend, health, shutdown/restart, and packaged isolation checks are executed and recorded in the release checklist.
