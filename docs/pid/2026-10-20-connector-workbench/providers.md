# 基础配置：厂商预设与接入要求

## 1. 范围规则

目标是“项目支持的官方厂商均能从界面选择”，并扩大可直接使用的预设。厂商目录、服务协议、模型目录、凭据和连接测试共同构成一次接入；单独增加一个下拉框选项不算完成。

下表是本版拟交付范围，不是当前已实现能力声明。开发时按实际服务分别注册；同一家厂商不必提供全部七类服务。用户选择生图时只列生图档案，选择 STT 时只列 STT 档案。

## 2. 厂商目录

| 分组 | 本版预设 | 开发范围 |
|---|---|---|
| 既有预设整理 | OpenAI、DeepSeek、阿里云百炼/通义千问、智谱 GLM | 将分散预设合并，完整配置、测试并用于调用 |
| 既有语音适配整理 | MiniMax、OpenAI-compatible 语音 | 将 provider 字符串输入改为可选厂商，保留自定义服务档案 |
| 新增模型官方厂商 | Anthropic Claude、Google Gemini、Moonshot Kimi、火山方舟/豆包、百度千帆、腾讯混元、讯飞星火 | 实现厂商所选模型的实际文本调用；按官方协议声明识图/Embedding 等用途 |
| 新增语音官方厂商 | 阿里云语音、火山引擎语音、讯飞语音、Fish Audio | 分别实现所选 STT/TTS 服务；按厂商要求提供 App ID、Key、Token、区域等字段 |
| 搜索服务 | 当前 AnySearch 接入、Tavily、Brave Search、博查 | 统一地址/密钥/区域表单与搜索结果结构，接入 AI 搜索工具 |
| 图像服务 | OpenAI、Google、阿里云、火山引擎、MiniMax | 实现该厂商实际开放的识图或生图协议，按服务类型显示 |
| 托管与聚合 | Azure OpenAI、SiliconFlow、OpenRouter | 单列托管/聚合分类，不能显示为模型原厂 |
| 本地 | Ollama、LM Studio、自定义 OpenAI-compatible | 可由发现流程导入；明确本地地址和实际协议 |

本版范围中的每个预设需要至少完成所列分组对应服务的实际请求。一个厂商提供多个用途时，各用途独立验证；不能用聊天成功推导语音、生图也成功。

厂商对服务、区域和模型的支持会调整，预设目录必须带 `official_docs_url` 与最近核对日期。模型名称不固定为文档撰写时的“最新型号”；使用官方可查询目录或随应用维护的明确模型列表，并允许输入账户可用的模型 ID。

## 3. 已核对的官方依据

2026-10-20 查阅下列官方页面，仅用于协议设计，不把网页说明当作项目已实现或已通过连接测试。

- Google 提供 OpenAI 兼容接口，也推荐新项目使用原生 Gemini API。其文本兼容入口可用于现有聊天链路；原生音视频等用途仍按对应服务 API 接入。[Google 官方兼容文档](https://ai.google.dev/gemini-api/docs/openai)
- Anthropic 提供 OpenAI SDK 兼容层。接入时必须核对字段和功能差异，不能将所有 OpenAI 特性视为等价支持。[Claude 官方兼容文档](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk)
- MiniMax 提供 OpenAI SDK 调用说明；该文档用于文本服务，语音配置仍按语音服务协议分别实现。[MiniMax 官方文本接口](https://platform.minimax.cn/docs/api-reference/text-openai-api)
- 百炼提供千问官方 API 和 OpenAI 兼容 API，并区分区域地址。区域选择必须与账户、密钥和模型可用性对应。[阿里云官方产品说明](https://www.alibabacloud.com/help/zh/model-studio/what-is-model-studio)

其余拟新增厂商在 D03 中核对官方文档并写入预设记录；本文件不编造未核对的 API 地址、鉴权规则或模型 ID。上述厂商均属于开发交付清单，不能仅以“需要核对”为由省略接入。

## 4. 多厂商、模型档案与模型池

可以连续添加多家官方厂商，也可为同一厂商添加多个账户。选择预设是创建/编辑账户的步骤，不是覆盖全局唯一厂商。厂商账户持有凭据，多个模型档案引用该账户，多个模型池再引用这些档案。

对话、识图、生图分别配置分级模型池。一级候选不可用时按顺序尝试下一候选和下一级，并显示切换提示。具体调度、错误分类和验收见 [分级模型池](model-pools.md)。固定档案仍可直接绑定；不自动向用户的池添加其他厂商。

## 5. 配置流程

1. 点击服务类别，例如“语音合成”。
2. 在弹窗厂商列表中选择 MiniMax 或其他语音厂商。
3. 选择区域；由预设填入官方 API 地址及对应鉴权字段。
4. 输入或选择凭据，选择模型与音色；高级参数在弹窗内切换标签页。
5. 保存档案，发起该服务的测试。
6. 测试结果在弹窗中显示；模型档案可加入指定池的某一级，并在连接器绑定给智能体；独立语音服务按档案配置。

配置列表可以按厂商名称过滤，这是本地配置选择，不恢复已移除的联网搜索页。

## 6. 预设交付记录

每个预设记录以下内容：

```text
厂商与服务：
官方文档 URL：
核对日期：
区域与 API 地址：
协议/adapter：
必填鉴权字段：
使用的模型 ID：
测试请求类型：
实际结果：
验证日期：
关联缺陷：
```

记录中不包含密钥、完整认证头或账户敏感数据。验收使用真实账号执行最小有效请求；缺少账号的项列为“待提供测试账号”，明确对应厂商，继续完成其他可测试项，不将整项功能改为展示占位。
