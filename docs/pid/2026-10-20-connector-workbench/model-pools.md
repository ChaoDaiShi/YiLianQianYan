# 多厂商与分级模型池

## 1. 配置对象

采用三个对象层次：

1. **厂商账户 ProviderAccount**：厂商预设、账户别名、区域、地址、凭据引用。可同时添加多家厂商，同厂商也可添加不同账户。
2. **模型档案 ServiceProfile**：关联一个账户，记录模型 ID、用途、参数和实际支持的能力；一个账户可添加多个模型。
3. **模型池 ModelPool**：引用模型档案，排列为一级、二级、三级等。不同池可复用同一个档案，编辑池不复制密钥。

对话、识图、生图分别建池，不能把不同用途的模型混在同一条调用链。Embedding 仍使用独立档案，不能因服务错误就换成不同向量空间的模型。STT、TTS 和搜索仍按各自已选服务执行；本次自动降级范围是用户配置的模型池。

## 2. 页面与操作

基础配置的模型页上方显示已添加厂商卡片，提供“添加厂商”“管理模型”；下方显示当前模型池和各级候选。多个池通过选择器切换，新增池在弹窗完成。

每一级显示顺序、候选厂商/模型、用途、可用状态和本轮是否正在使用。提供添加候选、移除候选、移动层级、同层排序。移除候选只修改该池；删除厂商账户时列出受影响档案及模型池，在用户选择替换或移除引用后保存，不能留下失效引用。

模型池必须至少有一个已启用且用途匹配的候选。同一档案在一个池内只出现一次。用户保存后生成新版本；运行中的请求固定使用开始时的版本，新请求采用更新版本。

连接器的模型节点可选择“使用模型池”或“固定模型档案”。池绑定显示池名、层数和当前实际使用模型；固定档案不隐式加入其他候选。

## 3. 调度语义

层级从小到大、同层按显式顺序串行尝试。一个请求不得并发向多个厂商竞速，也不自行增加厂商。候选不可用时转到下一候选；同层还有候选时先换同层，当前层用尽才降级。

失败分类：

| 情形 | 行为 |
|---|---|
| 连接失败、断开、超时、服务 5xx、限流 | 记录原因并转下一候选 |
| 明确额度耗尽、认证失败、指定模型下线/不存在 | 记录可操作原因并转下一候选，提示检查对应账户/模型 |
| 用户取消、应用停止 | 立即终止本轮，不继续换模型 |
| 工具权限禁止、待审批 | 由权限流程处理，不触发模型降级 |
| 模型内容拒绝 | 作为该次正常模型结果处理，不用其他模型绕过 |
| 参数/请求结构错误、请求超出所有候选能力 | 返回具体配置或请求错误，不循环尝试 |

仅将已登记的厂商错误码映射到上述类型，不能把所有 HTTP 4xx 都归为认证或额度错误。异常分类返回明确枚举，由调度器统一使用。

每个候选在同一请求内最多一次。池配置包含候选超时与本轮总时限；切换不得重置总时限。停止信号贯穿当前请求和后续候选。池中所有候选失败后返回一份汇总，显示实际尝试顺序和原因。

下一次请求从一级重新开始，不建立后台自动探测和跨请求熔断系统。上一次使用下级、新请求成功使用一级时发送恢复事件。正在生成的回答保持当前模型，不中途切回。

## 4. 流式回答与工具调用

- 首个 token 之前失败：切换候选，保持同一个回复位置，显示切换提示。
- 已输出部分文本后失败：将当前片段标为“回答中断”，展示切换原因；新候选从同一轮输入重新生成，替换当前正文。保留“查看中断片段”入口，不拼接不同模型的残句冒充一个完整回答。
- 结构化工具调用尚未完整接收：不执行不完整调用，丢弃该尝试的半成品参数。
- 工具已成功执行：记录结果已提交给本轮上下文。后续模型请求失败时只重新选择用于后续推理的模型，不能重放已经完成的工具动作。
- 审批已批准的具体工具调用不因换模型重新执行。新模型提出的新动作仍走原执行网关。

调度边界是一条模型请求，不能通过从头重跑整段 Agent 或工作流来实现降级。沿用现有工具执行记录、轮次和取消机制。

## 5. 事件与用户提示

新增模型路由事件，接入现有 SSE：

```ts
interface ModelRouteEvent {
  type: "model_route";
  request_id: string;
  conversation_id: string;
  pool_id: string;
  pool_revision: number;
  attempt_id: string;
  phase: "selected" | "switched" | "recovered" | "exhausted";
  from_profile_id: string | null;
  to_profile_id: string | null;
  from_tier: number | null;
  to_tier: number | null;
  reason: "network" | "timeout" | "rate_limit" | "quota"
    | "authentication" | "model_unavailable" | "service_error" | null;
}
```

前端按 attempt_id 去重事件，不能每个 token 重复弹提示。对话内状态条始终显示本轮实际使用模型；跨层切换弹出一次简短提示，记录保留在该轮详情。通话浮窗显示“已切换到二级模型”等简短文字；不打断用户话语播放长错误信息。

全部不可用显示“本轮所有候选均不可用”，列出已尝试项，并提供“打开模型池”和用户主动重试。重试建立新 request_id，不复用旧请求的失败状态。

## 6. 用量与可观测性

每个实际厂商请求独立记录 attempt_id、厂商、模型、层级、开始/结束时间、失败类别和 usage。业务轮次通过 request_id 汇总；不能因为一次回复尝试了两家，就丢弃失败但已消耗 Token 的调用。未知 usage 保持未知。

当前模型、使用过的候选、降级和恢复事件在对话、连接器和监控中使用同一数据源。日志不包含密钥和认证头。厂商原始错误不直接填入面向用户的提示。

## 7. 开发接入

沿用当前 `backend/src/integrations/llm/client.rs` 的请求与流解析，新增模型池选择层；选择层只返回具体 ServiceProfile 和有界尝试顺序。权限、工具执行、对话保存仍使用既有路径。

拟新增：

- `backend/src/modules/settings/domain/model_pool.rs`：配置和版本类型。
- `backend/src/integrations/llm/model_pool.rs`：顺序调度、错误分类与路由事件。
- `backend/src/api/model_pools.rs`：厂商账户及模型池 API。
- `frontend/src/features/settings/components/ModelPoolPanel.tsx`：层级可视化。
- `frontend/src/features/settings/components/ProviderAccountDialog.tsx`：多厂商账户编辑。
- `frontend/src/features/settings/components/ModelPoolDialog.tsx`：池、层级和候选编辑。
- `frontend/src/features/chat/ModelRouteNotice.tsx`：对话切换通知。

测试使用本机受控服务返回超时、429、5xx、部分流和 usage，以检验调度细节；随后至少使用两家真实厂商完成一次一级不可用、二级成功的端到端操作。厂商连接测试和模型池顺序测试分别记录，不能互相替代。
