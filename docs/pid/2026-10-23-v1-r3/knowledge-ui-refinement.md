# 知识构建与页面适配修订

本次针对用户提供的五张实际截图修改，继续沿用既有昔涟主题、背景、导航和组件。基于现有未提交的R3工作继续开发，没有切换分支、提交或推送。

## 实际问题与修改

- 深度构建：原请求仅靠提示词要求JSON，综合示例还引用不存在的节点/论点。现在仅知识构建显式请求`json_object`输出，模型池候选同步生效；示例引用与必填字段一致。接受完整JSON对象或单一完整JSON围栏；截断、语法和字段错误分别记录，不保存原始模型正文，不增加重试或自动修补。
- 构建界面：主题输入上方右侧只有“快速”“深度”，开始按钮居中，底部留白；历史移到独立弹窗，选择记录后查看结构、对比与来源。
- 文件夹：新增1057迁移，保存分类及完整相对路径。正文继续按hash去重，同一文档可归属不同文件夹；列表与检索均支持分类筛选。
- 导入结果：独立弹窗显示进度、汇总、失败筛选和每页50条结果，不再向主页面追加大量通知。
- 字符限制：取消额外2,000,000字符全文限制，25MiB文件及原容器解析边界继续生效。预览仍为12,000字符；完整正文入库及检索不使用预览文本。
- 页面滚动：账号、日志、系统、搜索、智能体与技能/插件/能力管理明确使用定高工作区，列表、左侧导航与详情各自滚动。
- 设置节点：恢复坐标时也做实际碰撞检查，保留无冲突的拖拽坐标；设置节点统一220×80逻辑尺寸。
- 图像页面：直接展示识图/生图服务档案和实际调用操作，模型池放在高级折叠区，复用现有服务接口。

当前普通知识构建入口改为三个依次执行的阶段：知识层级、论点与冲突、来源分类。程序组装既有`BuildResult`；下一轮查询由独立规划请求返回。新增`prompts.rs`和`stages.rs`，保留原有JSON严格解析、逐字引用核对、图谱关系检查、来源分类规则、取消和数据库状态检查。没有增加自动重试、忽略字段、响应修补或模型切换。前端样式、公共接口、持久化结果格式和数据库结构保持不变。

每轮只评估新加入的来源，已分类的旧来源继续使用原评估。知识层级、论点和来源评估每次输出上限4096 token，查询规划上限512 token，且都服从所选模型更小的配置值。通常快速构建为4次模型请求，深度三轮为12次；没有新增来源的轮次省略来源分类请求。分阶段增加了请求次数，同时减少每个响应的结构复杂度，并不承诺在所有模型下总费用更低。
