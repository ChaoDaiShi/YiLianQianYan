## 使用入口与原页面适配

1. 知识库 → **AI 构建知识**：输入“构建数据结构知识体系”等主题，选择快速或深度。构建记录持久化；结果分为知识结构、对比与分歧、来源三个视图。完成后点击“导入知识库”，再次打开该文档可以回看构建来源。
2. 记忆 → 选中原有记忆：查看来源、作用域和版本；纠正保留历史；撤回后在“已撤回”中查看。撤回的内容不参与后续召回。
3. 能力 → 工作流 → 原运行工作流／原编辑器 → **运行**：在运行窗口调整本次节点输入，执行结果显示在原 Inspector；不会把本次输入覆盖到已保存流程。
4. 聊天顶部保留原结构，增加工作空间关联和成果入口；需要补充信息时直接显示回答卡片。上传资料继续使用原附件入口，附件可预览、分类并与所属消息关联；历史图片按工具 `resource_id` 和上传轮次恢复到对应位置。
5. 更多 → 时间任务／消息渠道。时间任务选择已有工作流；渠道管理显示实际已实现的协议及账号状态。
6. 工作空间详情 → 学习：选择知识资料生成笔记与练习；代码操作仍从原 Git 管理进入。

知识构建使用已配置的搜索服务；知识构建和学习共同读取显式默认模型池，未绑定时读取激活模型档案，再使用既有配置。显式绑定无效时返回具体配置错误。没有为这些页面新增独立模型配置或自动选择另一家服务。

## 当前边界

- 记忆采用全量候选评分，尚未引入ANN/图推理/神经训练；版本与撤回未扩展为跨设备治理同步、备份删除或完整双时间支持图。
- OCR文档流水线与源图编辑接口尚未实现；不会将普通读图、文本生图或通用Webhook改名为这些能力。
- 学习当前为单选客观题；每份资料取明确的有限摘录，生成语义质量仍取决于所选模型。
- PPTX当前表格转为可编辑正文行；本地OOXML回读不代替PowerPoint实际排版验证。
- 飞书官方长连接已实现，但真实账号收发仅在 QQ 与微信账号验证，飞书仅完成受控协议验证；OneBot 反向 WebSocket 依赖用户自备兼容服务。麦克风/扬声器和外部 LSP 服务不由受控协议测试代替。
- 安装包发布、真实外部服务验收和Git提交推送不是本次已完成动作。

因此，本报告记录实际完成的功能与验证，不将整个R3所有长期扩展都标为已交付。
