# 忆涟千言 · YiLianQianYan

忆涟千言是一个以本地工作空间为中心的桌面 AI 助手。你可以和它讨论问题，也可以把文件、资料和具体目标交给它，让它调用工具、处理任务，并在同一个工作台里查看执行过程和结果。

做这个项目，是希望把分散在聊天窗口、文件夹和各类工具里的工作接起来：读完一份资料后可以继续整理成文稿，讨论过的方案可以变成任务，一次有用的操作也可以保存成技能或工作流。对话保留上下文，工作空间保存文件与成果，执行记录则用来回答“刚才做了什么、做到了哪一步”。

项目采用 Rust、React 和 Tauri，主要入口是桌面客户端。当前源码版本为 `1.2.0`，提供 Windows x64 和 Apple Silicon Mac 的打包流程；浏览器模式用于开发和预览。本地核心功能无需登录，模型、搜索、语音和消息平台需要分别配置相应服务。

## 可以用它做什么

### 围绕一件事持续对话

对话页支持流式回答、附件、模型切换和执行过程查看。模型返回推理内容时，可以展开阅读；这些内容会随对话历史保存。工具调用、审批、执行错误和结果验证也有各自的展示位置，遇到问题时可以找到具体停在哪一步。

普通对话默认使用自动模式，可在输入栏切换聊天、工作或创造。自动模式按本轮请求和近期上下文选择交流、查阅或执行的能力范围。明确的只读限制会收窄工具范围，实际操作仍由原有权限网关检查。模型设置菜单可以指定智能体。内置角色沿用现有智能体管理页编辑表达风格和生成设置。

当前轮次执行中可在输入栏发送「任务进度」或「取消当前任务」。有补充或更正时，用「补充给当前任务：…」或「纠正当前任务：…」发给正在执行的轮次。已完成的工具结果保留，后续步骤使用更新后的要求。绑定到当前已确认目标的会话还支持暂停和继续目标。

普通对话可发送「新任务：…」启动独立后台运行。当前运行忙碌时，普通新消息会按内容进入同一会话的并行聊天或工作运行。使用顶部的「并行运行」查看和切换，进度、审批、补问与停止均指向当前选中的运行。恢复审批或补问后，模型继续处理时也可补充要求。

在「记忆 → 待审阅」可检查从用户消息提取的候选及通过验收的任务经验。确认前可以查看来源、编辑内容和选择适用范围。来源已移除的候选只能忽略。验收过程和数据范围见[并行对话与记忆审阅验收](docs/superpowers/plans/2026-11-13-parallel-conversations-and-memory-review.md)。

需要把一段对话整理成图时，在「记忆 → 待审阅 → 从对话提取」选择「关系图谱」和来源对话。当前模型从所选对话的近期用户消息中提出人物（含亲属）、事件、项目和概念关系。每条候选须能在一条来源消息中核对两端和摘引；可调整类型、关系、方向和确认状态，保存后在长期记忆的「关系图谱」中按类型查看。未审阅的候选不进入图谱，保留「待确认」的已保存关系以虚线显示。关系结构当前保存在本地记忆元数据中。

长期记忆的「关系图谱」默认投影当前有效记忆和已确认对应关系；打开「显示待确认」可查看已保存的待确认关系。「立体查看」按每条记忆实际发生的变更显示版本，按住中键拖动改变视角，点击版本查看正文和来源。对应关系有独立历史；通过关联纠正提交并审阅，才会改动另一条记忆。详见[记忆网络与版本迁移](docs/superpowers/plans/2026-11-15-memory-network-space.md)。

回答中的资料引用可定位到对应正文版本及位置。与本轮搜索结果对应的网页链接可打开来源摘要，点击后才打开原网页。

开发与验证记录见[智能交互升级的工程审计与验收](docs/superpowers/plans/2026-11-13-interaction-routing.md)。

长回复在生成和完成后使用相同的 Markdown 布局。模型达到单次输出上限时，会在本轮自动续写并追加到同一条回复。续写受本轮预算和轮数限制，也可以随时停止，已完成的片段会保留在对话里。

复杂操作按步骤之间的依赖推进。助手可在同一轮安排互不依赖的读取，再用读取结果决定后续操作。文件、公开搜索、内置网页和已授权软件优先使用对应的专用工具。

助手会结合当前话题理解简短请求。例如，“短一点”会直接给出刚才文案的精简版。在绑定目录的工作空间会话中，单独说“查看下”会默认快速查看该空间，优先读取根目录的 README 或项目说明。

如果一个问题有几种思路，可以从已有回答新建分支，再沿着新路径继续。原来的对话会保留，创建分支本身不会调用模型。对话画布按对话组展示主线与分支，节点保留摘要，选中后在详情区阅读完整 Markdown、模型思考与附件。选中历史节点用于阅读，输入栏继续在当前路径末尾追加消息。

界面采用固定导航和工作区，列表使用统一的标题与操作栏，配置和详情按需打开。聊天历史与执行上下文可以收起，为正文留出空间。Cyrene 主题为白天和夜间提供内置背景，跟随系统时会随系统外观切换。也可以在界面外观中上传自己的背景图。桌面主窗口关闭后进入托盘，可以从托盘恢复或退出应用。

### 把文件、任务和成果放进工作空间

工作空间关联本机项目目录，集中查看文件、任务、执行记录和产物。文件树可以打开预览，聊天附件与画布也复用同一个预览入口。读取工作空间文件时使用只读接口，不会为了预览再复制一份上传资源。

工作空间总览以项目卡片显示目录和项目状态，使用中的卡片可以直接打开文件、学习与创作。Windows 桌面端的新建与编辑弹窗可先选择文件夹，新建时会用文件夹名预填空间名称。也可以手动填写目录。卡片菜单提供「设为默认工作空间」，默认空间排在最前，并用于此后新建的普通对话。从具体空间发起对话时，沿用该空间。

工作空间按「使用中」和「已归档」分开。归档后可以在「已归档」页签恢复空间，也可以确认删除工作空间入口。关联的本地文件、对话、任务及成果记录会保留。

点「批量整理」可在当前页签里分多次搜索并累积勾选。全选和取消全选只作用于当前搜索结果。在「使用中」可批量归档，在「已归档」可批量恢复或删除，删除确认会列出全部选中的空间。批量操作部分失败时会显示失败原因，仍在列表的失败项会保持选中。

「查看已选」汇总当前页签的全部勾选，标出搜索结果里未显示的空间。可以逐项取消勾选或一键清空，在弹窗内也可以撤销刚才的清空。

预览支持以下内容：

| 类型 | 预览方式 |
| --- | --- |
| Markdown、文本与代码 | 阅读正文，文本内容可搜索 |
| DOCX | 展示标题、段落样式、表格和内嵌图片，支持长正文搜索 |
| XLSX / XLS | 切换工作表，查看单元格内容 |
| PPTX | 按页查看正文、表格与图片 |
| RTF | 阅读正文与基本样式 |
| PDF | 显示原文件；扫描页可以视觉阅读 |
| 图片 | 图片预览与缩放 |
| 音频、视频 | 使用 WebView 或浏览器支持的播放器 |
| ZIP | 查看压缩包目录条目 |

Office 预览侧重内容阅读，不保证复现原文件的分页、母版和复杂布局。旧版 DOC、PPT 尚不支持内置内容解析，RTF 的复杂表格和图片也未覆盖。扫描 PDF 不会凭空生成 OCR 文本，音视频是否能播放取决于当前环境支持的编码。

工作空间还提供资料学习和创作文稿页面。文稿保存为本地资源，保留历史版本；保存新版本时检查当前修订号，避免把较新的内容直接覆盖掉。

### 让任务有执行过程，也有交付结果

对于需要多步完成的目标，可以使用任务管理和工作流。任务记录计划、每次执行、审批、状态变化及最终产物；重试会创建新的执行尝试，历史记录继续保留。中断的运行会在恢复时标记相应状态，便于决定下一步如何处理。

工作流提供图形编辑器、运行参数、节点结果和运行历史。它使用有向无环图组织步骤，支持工具、MCP、子智能体、模型、条件和输出等节点。当前调度按顺序执行；模型节点本身只调用模型，带工具操作的节点仍进入统一安全执行链。

任务相关的 ProofLoop 提供验收条件、检查点、证据、评估与修复记录。它的作用是让交付结果有据可查。具体任务能否判定完成，仍取决于验收条件和实际取得的证据。

已确认的目标可以关联到对话。对话顶部、任务画布和工作空间的“任务 → 目标任务”使用同一目标与执行记录，显示正在处理的步骤或目标对话、阻塞原因、待审批或补充的信息，以及交付物入口。刷新或重启后会重新读取本地记录；工作空间中的目标选择也保留在页面地址中。失败可以定位到对应节点或对话，再使用原有重跑、重试及检查点功能恢复。

“取消任务”会停止该任务图及关联的目标对话，阻止后续步骤和取消后的审批恢复；对话输入框的停止按钮只停止当前一轮。目标完成仍须有通过当前验收的真实产物，聊天结束或工具返回成功不会代替交付验收。文件发生变化或记录过期时，需要重新验收。

目标绑定、对话状态、产物和验收变化会通过应用事件同步，断线后自动重连并补读已保存的状态。“刷新状态”只读取；执行成功或产物登记后会核验已有结果，也可手动“核验产物”。可用操作根据图控制、依赖、执行器及预算决定，审批继续使用现有核对入口；取消会一并清理该目标遗留的待审批和待回答事项。

“权限与提醒”可查看当前审批模式并选择该目标是否接收应用内轻通知。首次打开历史任务保持安静，后续需要决定、失败、中断、重新验收或验收通过时提醒；同一状态跨入口去重。应用处于后台时保留最新提醒，返回后显示。静默只影响提醒，不改变权限或任务执行。

定时任务支持一次、每日和每周等计划。应用需要保持运行，不能把本机调度理解为关机后仍会执行的云端服务。

个人主动助手第一阶段也从“更多 → 时间任务 → 新建任务”进入：任务类型选择“个人主动助手”，保存持续目标、工作空间和最多执行轮次，可按计划跟进或立即运行。助手回到同一任务对话，依据历史与文件状态推进工作，维护待办，遇到问题等待回答或审批，并将本轮报告保存在运行历史。可用“读取 notes.txt → 创建新的 report.md → 读回核验 → 汇报”体验本地执行闭环。

当前委托工具限定为目录内文件读取、新文件创建、待办和提问；须显式勾选文件创建权限，不能覆盖旧文件，不开放 shell、网络、桌面控制或消息账号。保存时固定授权目录；文件工具使用该目录内的绝对路径。每个连续执行段限制为 6 次模型调用、24,000 token 和 3 分钟，模型未返回可信用量时停止。每个委托总计最多 20 个执行轮次（默认 5，手动运行也计数）；人工确认后的继续执行段重新受同样限制，模型费用取决于所选服务。

关闭面板、切换页面或刷新不取消后台工作。暂停计划只停后续触发；“停止委托”同时暂停计划并取消当前轮次、问题和审批。进程退出后保留中断记录，失败、停止、中断或结果不确定时不自动重放，需检查任务对话后显式运行。已完成的文件操作不会回滚。这是受限的个人委托闭环，尚不包含应用挂载、账号代答或关机后常驻执行。实现与验收记录见[个人主动助手第一阶段](docs/superpowers/plans/2026-10-30-personal-proactive-assistant.md)。

个人助手还可在编辑弹窗的“重复方式”中选择“本地文件内容变化”，填写授权目录内现有文件的绝对路径（最多 1 MiB）。应用每 10 秒检查内容，变化后继续同一个委托会话；重复内容不触发，忙碌期间合并最新变化。保存和重新启用会以当前内容建立基线，不追补暂停期间的变化；进程重启保留已消费游标，失败或执行中断仍须显式运行恢复。文件被删除、超限或不可读时，列表显示监听错误。报告继续保存，完成弹出提示按同一委托每五分钟最多一次；当前任务对话内不重复提示，待审批和提问不受完成提示限频影响。详见[本地文件事件增量](docs/superpowers/plans/2026-10-31-personal-file-events.md)。

资料路径未知时，可在个人助手编辑弹窗中单独勾选“允许查找授权目录中的资料”，使用有界 `glob`/`grep` 查找文件名和文本；旧委托默认关闭。查找仍需安全设置中的目录递归读取授权；若目录中有拒绝或需要单独审批的子路径，须缩小搜索范围或逐文件处理，搜索批准不会覆盖这些限制。隐藏、依赖和构建目录默认排除；超限、不可读、链接和非文本跳过会明确报告不完整。创建文件仍需单独勾选，不能覆盖已有文件。可用“找到 source 中的 Markdown 资料，结合两份输入生成新的报告并读回核验”验证结构化工作闭环；这不等于真实模型质量已经验收。详见[资料发现阶段记录](docs/superpowers/plans/2026-11-01-personal-file-discovery.md)。

个人委托的“任务详情”集中提供概览与操作、执行过程、报告与文件、全部历史：可检查运行准备情况、具体审批/提问与工具核验，分页查看旧轮次，并只读预览真实生成文件。失败、取消或中断后须核对指定轮次，再明确继续新一轮；响应丢失可核对原请求，不重复创建执行。遇到遗留审批或未闭合工具记录，先“停止委托”清理并核实不确定结果，不自动重放。归档会停止当前轮次并保留记录与文件；恢复归档保持暂停。任务列表支持搜索、需要处理和归档筛选，读取失败仍可发送安全停止。授权目录固定，不随工作空间设置在后台变化；切换工作空间须重新勾选新增权限。详情预览会拒绝已修改、越界或已撤销读取权限的文件。完整覆盖与验收边界见[日常管理完善批次](docs/superpowers/plans/2026-11-01-personal-product-completion.md)。

### 积累记忆，整理自己的知识资料

记忆用于保留事实、偏好、知识和笔记，为后续对话与任务提供上下文。页面可以按分类筛选、查看详情和历史版本，也可以纠正或撤回已有记忆。检索支持词法、语义和混合方式；语义检索需要配置 Embedding 服务，索引状态和维护入口可以在页面查看。

词法召回优先匹配完整词和连续中文词组。聊天中省略主题的“还记得吗”会结合本对话最近的问题检索。候选按当前有效版本、采用范围和类别过滤后再排序。

在聊天中可以直接说“帮我记住，以后导出 CSV 用 UTF-8 编码”。助手会调用保存长期记忆工具，写入成功后确认，保存的内容可在记忆页查看。

可以在保存时说明范围。“只在本对话记住这次用 GBK”会随当前会话保留，包括长对话压缩后。“记住这个工作空间用 UTF-16”可在同一工作空间的新对话中召回。“以后各个对话都记住我默认用 UTF-8”保存为当前档案的偏好，在有相关话题时跨对话召回。当前对话里最新的明确要求优先，其次使用会话、工作空间、档案记忆。普通聊天内容随本会话延续。

要修改已有记忆，可以直接说“之前记的 CSV 导出编码改成 UTF-8”或“撤回之前记的 CSV 导出编码”。目标明确时，助手会纠正或撤回原记录。可能匹配多条时，会先询问要操作哪一条。撤回后该记录退出长期记忆召回，历史版本仍可在记忆页查看。

新对话里也可以直接说“接着上次的方案做”或“找回上次聊的星桥发布方案”。助手会在同一工作空间的旧对话中查找。未绑定工作空间时，会查找同样未绑定工作空间的普通旧对话。找到明确来源后，助手会用标题和相关聊天片段继续；有多个候选时可以回复序号或标题。这项查找直接使用已有聊天记录，无需事先保存记忆。

知识库用于组织资料与来源，并提供 AI 构建入口。快速模式适合先整理一个主题，深度模式会进行多轮互补检索。当前快速模式执行一轮、四条查询，深度模式执行三轮、最多十八条查询，保留最多四十八个去重来源。DeepSeek 深度研究每轮还会读取最多四页原文，把取得的摘录用于来源和引文核对；读取失败时会显示失败并保留已有材料。

新导入的文档优先按标题、段落、表格换行和幻灯片页切片，单片上限为 1,200 个字符。搜索和聊天引用从完整原文按结构取摘录，已有资料也能使用新的摘录方式。

搜索结果可以继续交给助手、创建任务或保存为知识记忆。使用搜索、网页读取和 AI 构建时，请先配置对应模型与搜索服务；这些步骤会向所选服务发出真实请求。

### 用技能、MCP 和角色扩展工作方式

内置工具负责文件读写、搜索、HTTP 请求、命令执行、进程管理、截图以及键鼠操作等原子能力。技能把一套操作方法写成可复用的步骤。应用默认展示随包提供的官方技能，也支持发现和预览其他软件的技能目录，再按实际兼容性导入。

MCP 用于接入外部工具服务。当前实现支持 stdio 和 Streamable HTTP，提供工具发现、资源读取以及提示词预览。接入服务、看到目录或安装插件，都不等于授予执行权限；调用工具时仍需经过本机安全策略。外部资源和提示词也不会仅因被预览就自动加入对话或系统提示词。

角色用于保存不同的工作偏好和提示词，团队与子智能体用于任务中的有限委派。当前多智能体任务按顺序执行，委派深度和执行数量有上限，并非并行运行的 Agent 集群。角色、技能和插件都不能自行扩大文件、网络或进程权限。

### 从桌面继续到语音和消息平台

桌面端提供语音会话与独立通话浮窗。语音需要配置对应的识别、合成服务及设备权限。隐藏通话浮窗会保留通话，结束通话使用单独的操作；监控浮窗也可以独立收起和关闭。

从聊天页开始通话后，普通提问沿用已绑定对话的上下文。从空白聊天页发起通话时，会先创建一个语音对话。

聊天框语音输入和通话中的单次录音会在检测到一句话结束后自动送去识别。聊天框收到的文字留在草稿中，也可以手动停止或取消录音。

「更多 → 软件挂载 → 消息渠道」按 QQ、微信和飞书组织会话，微信包含 iLink 和 Akasha-WeChat。每个渠道可以选择自动回复或审阅后发送，并使用保存好的角色、模型与回复预设。QQ 主人目标还可以查询授权范围内的好友、群和历史，向指定对象发信，或按计划运行目标。

QQ 会话列表与聊天标题优先显示已授权通讯录提供的好友备注、昵称或群名，并从 QQ 头像服务加载对应头像。群消息的发送人优先显示该群的群名片，其次显示昵称，并使用个人头像。仍可用原编号搜索会话，资料不可用时会显示编号和默认头像。

QQ / OneBot 插件可以集中管理已有 NapCatQQ 服务，并在应用内浏览器打开登录与管理页面。安装启用后，从“更多 → QQ 工作台”配置运行路径、启动或停止服务，并关联原有消息渠道。进程运行、管理页可达和 OneBot 连接分别显示；配置、协议与生命周期见[外部服务插件](docs/plugin-services.md)。

这些接入需要平台自己的应用权限、账号登录或外部服务。应用不会替你安装、登录 QQ，也不会仅凭本机连接成功就把消息标成送达。平台确认受理与联系人已阅读是两回事；发送结果未知时会保留未知状态。

具体配置、支持的消息类型和授权范围见[消息渠道说明](docs/message-channels.md)，微信 Akasha 的环境要求见[配套接入说明](docs/message-channels-akasha.md)。

## 第一次使用

当前开发版的七步向导支持填写称呼和交流偏好、选择各项设备和数据权限、检测本机设备、配置模型及选择默认工作空间。中途离开后可以继续，升级用户也可从“设置 → 个人资料与初始化”重新进入。向导完成后可从会话保存富交互成果到工作空间的“页面”页签。[富交互与页面](docs/workspace-pages-rich-chat.md) · [本地向量与 CLI 对话](docs/architecture/local-embedding-and-cli-chat.md) · [架构与升级说明](docs/implementation/2026-11-24-capability-upgrade/architecture.md)

如果只是使用应用，直接在 [Releases](https://github.com/ChaoDaiShi/YiLianQianYan/releases) 选择对应平台的安装包即可，不需要安装 Rust 或 Node.js。发布包对应某次发布，`develop` 和 `main` 上的新提交不会自动改写已经发布的安装包。

Windows 使用 x64 安装程序。Apple Silicon Mac 使用 arm64 DMG，打开后把应用拖进“应用程序”。现有发布说明中的 Windows 包未配置发布者代码签名，Mac 包采用临时签名、未经 Apple 公证；系统提示和校验方式见[安装说明](docs/releases/v1.2-installation.md)。

启动后建议按下面的顺序配置：

1. 在首次配置页选择模型服务商并填写自己的 API Key，软件会读取上游模型列表供选择。服务地址可按需展开修改，也可以接入自定义 OpenAI 兼容服务。
2. 点击“保存并测试连接”。应用会保存档案、发起真实连接测试、激活模型并确认可用状态，成功后再进入完成页。
3. 进入对话页，先发送一条简单问题，确认模型能够正常回答。
4. 需要处理本机资料时，再创建工作空间并选择目录。根据任务需要配置文件、网络、命令等权限。
5. 搜索、识图、生图、语音、消息渠道和账号同步都可以稍后配置，无需在第一次启动时全部填完。

选择“稍后配置”可以先浏览界面，但调用模型仍需要可用的模型配置。启动时会按聊天实际使用的模型来源检查就绪状态；已有可用模型会直接进入工作台，不因向导标志未完成而重复要求填写密钥。读取状态失败时显示无法确认，不当作尚未配置。

日常模型配置在“模型与服务”中完成，可选择已有账户或保存新凭据，多模态服务也可以复用账户。高级模型池供需要集中管理模型能力的场景使用，普通识图和生图无需先创建模型池。服务商返回 Token usage 时，应用会记录本地用量；未返回时不会估算成精确数字。

对话生成的图片保存后，会在对应的助手回复中显示缩略图，点击可放大查看。原图下载和待授权的图片仍可在对话顶部的“成果”中处理。

## 从源码运行

下面以 Windows / PowerShell 为例。仓库包含一个 Cargo workspace，后端和 Tauri 共享 Rust 实现，前端依赖单独安装。

### 准备环境

- Node.js 22 或 24，以及 npm；仓库 CI 使用 Node.js 22。
- Rust stable 与 Cargo。
- Windows 的 MSVC C++ 构建工具和 Windows SDK，通常通过 Visual Studio Build Tools 安装。
- Microsoft Edge WebView2 Runtime，用于 Tauri 桌面界面。

克隆后，在仓库根目录安装桌面 CLI 和前端依赖：

```powershell
git clone https://github.com/ChaoDaiShi/YiLianQianYan.git
cd YiLianQianYan
npm ci
npm --prefix frontend ci
```

依赖已安装且锁文件没有变化时，无需每次重新安装。

### 启动桌面客户端

在仓库根目录运行：

```powershell
npm run tauri:dev
```

Tauri 会启动前端开发服务，并在桌面进程内启动本地 Rust 后端。此时不要再单独运行一个占用 `9420` 端口的后端。

桌面客户端默认以 `1440 × 900` 逻辑像素为窗口目标，启动时根据屏幕工作区和缩放调整、居中，最小内尺寸为 `800 × 600`。本地控制会话令牌由 Tauri 在启动时生成，再通过内部命令交给 WebView，无需手动填写。

开发服务使用以下地址：

| 服务 | 默认地址 | 用途 |
| --- | --- | --- |
| Vite | `http://localhost:1420` | 桌面开发页面与浏览器预览 |
| Rust / Axum | `http://127.0.0.1:9420` | 本地 API、SSE 与工具运行时 |

### 单独调试后端和浏览器界面

需要分别观察前后端日志时，可以使用两个 PowerShell 终端。两边的控制会话令牌必须相同，且至少有 32 个字符。下面是仅供本机开发的示例值，请换成自己的随机值，不要提交到仓库。

终端一，从仓库根目录启动后端：

```powershell
$env:YILIAN_CONTROL_SESSION_TOKEN = "replace-with-your-local-random-token-at-least-32-chars"
cargo run -p yilian-backend --bin yilian-server
```

终端二，从仓库根目录启动前端：

```powershell
$env:VITE_CONTROL_SESSION_TOKEN = "replace-with-your-local-random-token-at-least-32-chars"
npm --prefix frontend run dev
```

打开 `http://localhost:1420`，按首次配置流程连接模型。若沿用默认模型的环境变量配置，也可以在启动后端前设置 `OPENAI_API_KEY`；自定义服务地址和模型名称仍应在应用中配置。

`VITE_*` 变量会进入开发页面或构建产物，`VITE_CONTROL_SESSION_TOKEN` 只用于本机调试，不能用来保存模型 API Key。

### 启动时遇到问题

- 提示 `9420` 端口不可用时，先检查是否已经打开桌面客户端或独立后端。关闭主窗口只会收到托盘，需要从托盘退出应用，才能结束该桌面进程。
- 浏览器请求返回 `401` 或提示控制会话无效时，检查两个终端的令牌是否完全相同、长度是否足够。修改 `VITE_CONTROL_SESSION_TOKEN` 后需要重启 Vite，单纯刷新页面不会重新读取启动环境变量。
- 界面能打开但模型连接失败时，核对服务地址、模型名称、账户凭据以及服务商权限。前端页面和健康检查可用，只能说明本地服务已启动，不能说明模型已经连通。
- 数据看起来与预期不同时，先核对 `YILIAN_DATA_DIR` 和当前身份档案。开发环境与日常使用环境可以指向不同目录，不必通过删除数据库来重新开始。

### 打包

在相应平台、仓库根目录运行：

```powershell
# Windows x64 安装包
npm run build:windows
```

```bash
# 在 macOS 上构建 app 与 DMG
npm run build:macos
```

完整脚本包含版本核对、构建和平台检查。发布工作流位于 [.github/workflows/release-v12.yml](.github/workflows/release-v12.yml)，安装包验证范围见[安装说明](docs/releases/v1.2-installation.md)。本机源码构建通过，不代表所有平台的安装、权限和实际 AI 服务都已验证。

## 配置、数据与隐私

### 本地数据放在哪里

应用使用 SQLite 保存本地配置与业务记录，文件资源存放在本地资源存储中。默认数据根目录是操作系统用户数据目录下的 `yilianqianyan-v1`，由 `dirs::data_dir()` 确定；Windows 上通常位于 `%APPDATA%\yilianqianyan-v1`。实际数据库路径由当前本地身份档案选择，不是仓库中的固定数据库文件。

开发时可以通过 `YILIAN_DATA_DIR` 指定独立的数据目录，避免调试记录混入日常使用的数据：

```powershell
$env:YILIAN_DATA_DIR = "F:\YiLianData\development"
npm run tauri:dev
```

其他常用环境变量：

| 变量 | 作用 |
| --- | --- |
| `YILIAN_WORKSPACE` | 指定运行时工作目录；已注册的项目工作空间仍有各自的目录范围 |
| `YILIAN_HOST` | 独立后端的监听地址，默认 `127.0.0.1:9420` |
| `YILIAN_CONTROL_SESSION_TOKEN` | 独立后端使用的本地控制会话令牌 |
| `VITE_CONTROL_SESSION_TOKEN` | 浏览器开发模式下与后端匹配的令牌 |
| `YILIAN_ALLOWED_ORIGINS` | 以逗号分隔，显式添加允许访问本地 API 的 Origin |
| `OPENAI_API_KEY` | 默认模型配置可读取的模型凭据环境变量 |
| `RUST_LOG` | 调整 Rust 日志级别 |

### 凭据和外部请求

模型、Embedding、语音、搜索与 MCP 等凭据通过系统凭据库管理。新配置在本地业务记录中保存凭据引用和配置状态，接口不回显密钥原文。不要把真实密钥放进 README、前端环境变量、测试输出或 Git 提交。

本地优先表示数据与运行时以本机为中心。使用在线模型时，相关对话与选取的上下文会发送到配置的模型服务；使用搜索、语音或消息渠道时，也会访问对应服务。文件预览本身走本地接口，不因打开预览就上传到外部服务。

### 账号与同步

游客模式可以使用本地核心功能。登录后，需要明确选择同步已有数据、保持仅本地或稍后决定；账号并不是启动条件。账号中心提供设备会话、同步状态、数据导出与注销入口。

公共仓库保留 Cloud Contract 和本地客户端。Cloud API、Admin 和服务端数据库实现位于独立私有仓库，不随桌面源码发布。同步、搜索和登录是否可用，取决于实际配置的服务与网络状态。

## 工具执行、审批与验证

忆涟千言可以读写文件、运行命令和控制桌面，因此“模型提出一个动作”和“允许这个动作执行”之间有明确的授权步骤。

工具调用统一进入 `SecurityExecutionGateway`，结合调用者角色、资源授权、路径或网络范围及风险等级作出决定。低风险操作通常自动执行；中等风险仍受权限与范围约束；高风险和严重风险操作需要明确批准。未知工具、无法确定的安全状态和明确拒绝规则不会被当作允许。

批准后执行的是审批保存的原始调用，执行前还会重新检查当前策略。同一审批最多消费一次。拒绝不会执行原工具，Agent 可以根据拒绝结果调整后续方案。待处理审批属于内存运行时状态，后端重启后会失效。

工具返回成功之后，支持的操作还会进入结果验证，例如重新检查文件内容或进程状态。工具结果与验证结果分别记录；“接口返回成功”不会直接等同于“任务已经完成”。验证能力有具体范围，不能据此声称所有桌面操作都已实现完整视觉验收。

执行过程中可以停止任务。Agent 保留每轮最多 20 轮执行的限制；同一个工具以相同参数连续三次返回相同失败或验证失败证据时，会停止本轮。成功操作或不同的参数、失败证据会重新计数，正常的多步读取和连续输入不会仅因工具名称重复就提前结束。

发送消息后的准备阶段也可以停止，包括运行配置准备和记忆检索。若在消息被接受前停止，本次用户消息不写入会话，也不再调用聊天模型；已经完成的文件操作不会回滚。审批或回答后的续跑准备阶段仍沿用原有停止行为。

正在准备、执行或等待审批、回答的对话暂不能删除，接口会提示先停止或完成当前轮次。运行结束后才删除会话及历史，避免删除记录后后台继续操作文件。个人委托对话还须先明确删除对应委托。

安全执行记录会脱敏并写入本地审计。命令进程使用受管进程与超时清理机制；路径授权和网络请求也有独立检查。这些措施有各自的覆盖范围，当前不提供容器级文件系统或网络命名空间隔离，审计也未实现防篡改签名。

## 项目结构与接口

### 运行关系

桌面客户端通过内嵌 WebView 显示 React 界面，在同一桌面进程中启动 Rust 本地服务。前端通过 HTTP 和 SSE 访问后端，Tauri IPC 处理控制会话、窗口与浮窗等桌面能力。

```text
Tauri 桌面进程
├── WebView：React + TypeScript + Vite + Zustand
│   ├── HTTP / SSE → 本地 Axum 服务
│   └── Tauri IPC → 桌面窗口与系统能力
└── Rust 后端
    ├── 对话与 Agent 循环
    ├── 工作空间 / 任务 / 工作流 / 记忆 / 知识
    ├── 工具注册与安全执行网关
    ├── 模型 / MCP / 消息平台等外部集成
    └── SQLite / 本地资源存储 / 系统凭据库
```

桌面控制使用 `enigo` 和 `xcap` 等库。实现新操作时优先使用结构化 API，再考虑 Windows UI Automation、视觉交互和坐标操作；工具执行仍应保留结果核验与取消能力。

## 软件接入与窗口会话（Windows 本地开发版）

软件窗口接入入口位于「更多 → 软件挂载 → 桌面软件」（`/software`）。登记 Windows 软件的完整 EXE 路径后，选中软件并点击「连接软件」。微信会筛选实际应用窗口，找到唯一目标时直接连接，并在兼容时嵌入。遇到多个无法区分的窗口时，再按窗口选择。未运行的软件仍可确认启动。

选择「通用 Windows 软件」可以登记其他桌面程序。连接窗口后，可以说“看看挂载窗口里有哪些选项”或“在挂载窗口里勾选自动换行”。同时连接多个软件时，可以直接说登记名称。开启控件观察后，忆涟千言能识别窗口中的按钮、列表、选项和编辑框。单独允许读取可见文字后，对话还可使用软件提供的屏内正文。获得操作许可并通过本次审批后，忆涟千言可填写单行文本、选中选项、勾选、展开、聚焦或点击控件。输入和状态修改通过控件回读核对，点击可核对新出现的指定文字。软件能提供的控件和文字取决于该窗口的 Windows UI Automation 支持。 自绘界面没有提供所需正文时，可单独允许「识别整个目标窗口的可见文字」。忆涟千言会在本机识别该窗口的一帧画面，再把识别文字提供给对话。

在微信登记中允许 AI 观察和请求控件操作，连接窗口并打开目标群后，可以直接对忆涟千言说“帮我在微信的 cs一群 把草稿补成 cs2，先别发”。软件会选定当前对话唯一可操作的微信窗口，提交本次草稿修改审批。通过后，它会核对群名、填写草稿并回读输入框，文字留在微信中待你发送。

要让 AI 阅读微信群聊，先在微信登记中勾选「允许 AI 观察」，再连接微信并打开目标群。点击「读取当前群聊」后，核对快照中的群名和选区，也可以拖动重选。点击「识别选区」进行本机中文 OCR，校对群名、发言人和消息后，点击「带入 AI 对话」，按需要编辑提问并发送。每次读取当前可见的一屏，查看更早的记录可以先在微信中向上滚动。

工作台提供独立显示、兼容窗口的嵌入／恢复、停止／恢复 AI 会话、操作记录和未知结果核对。兼容的桌面软件在挂载时保留自己的顶层窗口和输入队列，随工作台移动和调整大小，鼠标和键盘继续由目标软件处理。脱离时恢复挂载前的位置及显示状态。此方式已在 Windows 微信 4.2.0.13 验证。运行时检查 DPI 和窗口归属，其他版本及窗口形态以实际结果为准。正常离页、隐藏与退出会请求恢复已挂载窗口，恢复未确认时会报告错误或阻止正常关闭。强制结束或宿主硬崩溃没有独立恢复守护程序，嵌入前应了解这一限制。

2026-11-03 补验已在隔离 Tauri／WebView2 中通过 17 组受控窗口联调，并通过 8 组真实微信窗口兼容性检查。真实微信检查只使用窗口元数据，覆盖实际嵌入、尺寸变化、独立恢复、弹窗／离页及宿主正常退出恢复；未读取聊天、控件正文或截图，未登录、退出或收发消息。窗口恢复、显式显示和前台切换会等待实际状态完成，避免迟到的隐藏消息覆盖后续显示；本次结果不代表微信账号或聊天功能已验收。

点击「独立显示」会将当前窗口移回桌面，点击「嵌回忆涟千言」会继续使用同一个会话。独立显示以窗口脱离宿主且实际可见为准，Windows 的前台激活结果单独核对。微信重建窗口时，工作台会提示原窗口失效，点击「重新连接软件」可查找并连接当前窗口。

连接后的工作台以软件窗口为主：软件列表默认收起，可从顶部“软件列表”展开；会话状态和主要操作集中在紧凑工具栏，完整程序路径、窗口身份和进程归属放在“会话详情”弹窗。打开详情前仍先恢复原生窗口，关闭后可明确重新嵌入。

连接软件后，可按软件开启「后台监管」。监管在当前桌面宿主运行期间生效，监测进程退出、窗口关闭、窗口重建及该软件新增的 Windows 系统通知。打开软件的观察许可后，监管会对比当前连接窗口提供的控件状态。允许读取正文后，监管也会对比该窗口提供的文字。如果窗口只提供外层控件，可再开启窗口文字识别许可，让忆涟千言在本机识别目标窗口的文字。窗口被其他窗口盖住时，只要仍能获取该窗口的画面，文字识别就能继续工作。第一次读取建立基线，确认变化后，忆涟千言显示提示，并用当前配置的模型解释变化。系统通知依赖 Windows 的通知访问许可，开启时以现有通知为基线，之后按软件来源筛选新增通知。

微信窗口最小化后，如果该版本仍提供会话的 Windows UI Automation 数据，可继续读取当前打开的会话、已加载的消息和未发送草稿。在「登记与许可」中开启控件观察和正文读取后，可用「读取当前群聊」、在对话中让 AI 读取当前微信会话，或开启后台监管。最小化读取只访问当前会话，读取和监控期间保持窗口最小化。

微信监管按当前会话的已加载消息顺序对比，识别到追加消息时显示「微信当前会话有新消息」。日期和时间分隔行不计入消息。首次读取和切换会话时会重新建立基线。

微信已连接并允许观察和操作时，可以直接对忆涟千言说“在微信当前群里输入 cs”。忆涟千言会定位当前聊天的输入框，填入草稿，再从窗口回读核对。点名群聊时会先核对当前聊天标题，消息保留在草稿中。

AI 的 `software_sessions`、`software_observe`、`software_control` 复用现有 Gateway 与审批。控件观察及动作两项许可默认关闭，更换项目、路径或适配器需重新选择许可。UI Automation 观察有界控件结构而非完整聊天／窗口正文，不读取密码或 TextPattern；实际控件不提供所需模式时报告不可用。操作绑定会话代次和当次观察，停止、撤权、项目归档或窗口身份变化会阻止后续动作。已调用但无法证明业务结果的操作保留未知状态，核对不会重放原操作。实现范围与验证记录见[软件接入与微信适配批次](docs/superpowers/plans/2026-11-03-software-wechat-mount.md)。

## 内置浏览器与项目站点（本地开发版）

Windows 桌面端从「更多 → 浏览器」进入。网页使用原生 WebView2 内容视图，可以在主界面嵌入和独立窗口之间切换；切换保留同一页面及表单。离开浏览器页面会隐藏嵌入视图，关闭标签才关闭对应网页。聊天中的网页链接也默认走此入口；需要时可明确选择系统浏览器。纯 Vite 预览不提供原生浏览器能力。

浏览器使用紧凑的标签栏、导航／地址栏和项目站点快捷栏。主页与新建标签显示中部搜索框：网址和本地开发地址直接打开，关键词通过 Bing 搜索；收藏入口来自实际项目站点记录。标签支持独立关闭及键盘切换，地址栏、刷新、查找和缩放使用浏览器快捷键；工具入口提供原生查找、缩放、收藏和明确确认后的浏览数据清除。切回已有标签后会保留选择。独立窗口继续导航同一页面，新建标签会回到主窗口。

常规浏览默认保留本应用的浏览数据，支持网站允许的持续登录；退出应用后仍保留持久 Cookie 与网站存储，网站退出登录、过期或仅使用会话 Cookie 时仍可能要求重新登录。存储按实际应用账号资料目录及项目隔离；同一项目的常规标签共享登录和已由用户明确授权的本地站点，未关联项目使用该账号的个人浏览环境。可主动选择独立的临时浏览，关闭最后一个相关页面后清理临时数据。弹窗继承来源页面的浏览环境，关闭父标签不会提前破坏仍打开的子页面。不导入现有系统浏览器 Cookie。

「项目站点」按工作空间登记网址、用途、收藏和启动提示。相同 localhost 地址可登记在不同项目下；站点在线并不证明当前服务属于该项目，界面会保留归属未核实提示。启动提示仅保存文本，不执行命令、不关闭占用端口的进程。访问历史支持筛选；隐藏敏感参数的历史地址只作展示，可明确打开其仍有效的已登记站点。

AI 的 `visible_browser_*` 工具操作同一个可见原生标签，支持识别会话、导航、结构化读取、点击、输入、滚动和截图，继续经过现有执行 Gateway 与审批。旧观察在页面变化后失效；结果不确定时保留操作记录并暂停后续动作，由用户检查页面后在可信界面确认，确认不会重放原动作。截图进入已有成果系统。

同一标签的变更动作排队至上一操作回执完成后再执行；新出现的不确定结果会阻止已经排队的后续变更。「停止加载」也取消该标签已接收但尚未执行的请求，不影响其他标签。创建阶段取消或响应超时后，原生创建任务仍负责晚到资源的关闭，未完成安全初始化的标签不能被列出或操作。显示与隐藏按最新接受的窗口归属和顺序生效，分离与嵌回仍移动同一页面。

关闭确认以 UI 线程上的实际 WebView2 Controller 关闭回执为准。原生线程阻塞或创建未结束时会返回有界失败并保留清理责任，恢复后可再次完成关闭；迟到的独立窗口也在清理范围。对应回归包含真实原生调度暂停、取消、超时、焦点转移、反向迁移和关闭重试，见 [浏览器修复与紧凑布局记录](docs/superpowers/plans/2026-11-02-browser-fixes-and-compact-chrome.md)。

原生视图迁移使用随仓库保存的 `tauri-runtime-wry 2.11.4` 同版本局部补丁：迁移等待 UI 回执时释放父窗口 ID 锁，另用命令入队锁保持迁移与普通操作的顺序，避免原生焦点回调争用 ID 锁造成死锁。来源、许可证、精确修改范围及后续移除条件见 [运行时补丁说明](vendor/tauri-runtime-wry/PATCH.md)。

网页不具有主窗口的本地命令和工具权限。用户点击的新窗口链接进入受管理的标签页，脚本弹窗提供明确的打开／忽略入口，并保留原生窗口回调语义。网页可使用原生右键菜单、脚本对话框和手动文件选择；下载先等待用户选择保存位置，设备权限等待本次允许或拒绝，不自动永久授予。AI 的文件／密码输入限制仍保留，不提供任意本地文件路径赋值接口。

私网访问限定为已明确选定的本地站点，持续阻断应用控制端口。常规浏览的授权范围属于所选账号及项目的共享上下文；临时浏览仍为独立上下文。当前原生实现与实际验收以 Windows 为准，其他平台无可用 host 时明确报告不可用。功能、生命周期与验证范围见 [浏览器功能补全记录](docs/superpowers/plans/2026-11-02-browser-functional-completion.md)；较早版本的边界记录保留在 [初始实施记录](docs/superpowers/plans/2026-11-01-native-browser-project-sites.md)。
